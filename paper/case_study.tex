\section{Case Study: Knowledge-Grounded Features}
\label{sec:case_study}

To illustrate how KnowFeat leverages domain knowledge to generate interpretable, high-quality features, we present three representative case studies drawn from the heart disease and credit default datasets. Each example highlights a different aspect of knowledge-guided feature engineering: multi-source knowledge fusion, domain-specific normalization, and non-linear risk interaction.

\subsection{Case 1: Exercise Test Consistency Score (Heart)}
\label{subsec:case1}

\textbf{Feature:} \texttt{consistency\_score} --- a 0--3 ordinal score counting the number of abnormal channels in a cardiac exercise test.

\textbf{Knowledge assets used:}
\begin{itemize}
    \item \textit{EXP\_07} (Expert Opinion): ``Exercise testing provides three simultaneous diagnostic channels. Concordant positivity carries far higher risk than a single abnormal channel.''
    \item \textit{RULE\_009} (Detection Rule): Chronotropic incompetence --- MaxHR $< 0.85 \times (220 - \text{Age})$.
    \item \textit{RULE\_002} (Detection Rule): Exercise test positivity --- Oldpeak $\geq 1.0$mm with downsloping or flat ST segment.
    \item \textit{IND\_08} (Risk Indicator): Exercise-induced angina indicates myocardial ischemia.
\end{itemize}

\textbf{Reasoning chain:}
\begin{enumerate}
    \item From \textit{EXP\_07}: exercise tests provide three diagnostic channels --- hemodynamic, ECG morphology, and symptomatic. Concordance multiplicatively increases risk.
    \item From \textit{RULE\_009}: compute Channel~1 as MaxHR $< 0.85 \times (220 - \text{Age})$.
    \item From \textit{RULE\_002}: compute Channel~2 as Oldpeak $\geq 1.0$ AND ST\_Slope $\in$ \{Down, Flat\}.
    \item From \textit{IND\_08}: compute Channel~3 as ExerciseAngina $=$ `Y'.
    \item Sum three binary channels into a score (0--3).
\end{enumerate}

\textbf{Generated code (simplified):}
{\small
\begin{verbatim}
ch1 = (MaxHR < 0.85*(220-Age))
ch2 = (Oldpeak >= 1.0)
    & (ST_Slope.isin(['Down','Flat']))
ch3 = (ExerciseAngina == 'Y')
score = ch1 + ch2 + ch3
\end{verbatim}
}

\textbf{Why this matters.}
This feature fuses knowledge from four distinct assets spanning three clinical modalities. No individual column captures ``concordant positivity;'' it requires understanding that the \emph{combination} of hemodynamic failure, ECG changes, and symptoms is qualitatively different from any single abnormality. A purely data-driven method could discover pairwise interactions like MaxHR $\times$ Oldpeak, but would not produce a clinically meaningful tri-channel concordance score. The specific thresholds (0.85, 1.0mm) come from medical guidelines encoded in \textit{RULE\_009} and \textit{RULE\_002}.

\subsection{Case 2: Age-Corrected Heart Rate Reserve (Heart)}
\label{subsec:case2}

\textbf{Feature:} \texttt{hr\_ratio} $= \text{MaxHR} / (220 - \text{Age})$.

\textbf{Knowledge assets used:}
\begin{itemize}
    \item \textit{IND\_07}: Lower maximum heart rate indicates higher cardiovascular risk.
    \item \textit{EXP\_05}: ``Raw MaxHR is misleading without age correction. A 70-year-old with MaxHR=120 achieves 80\% of predicted (borderline), while a 40-year-old with MaxHR=120 reaches only 67\% (abnormal). Always use heart rate reserve ratio.''
\end{itemize}

\textbf{Reasoning chain:}
\begin{enumerate}
    \item From \textit{IND\_07}: lower MaxHR implies higher risk, but this is confounded by age.
    \item From \textit{EXP\_05}: the clinically correct measure is the \emph{ratio} of observed to predicted MaxHR (predicted $= 220 - \text{Age}$).
    \item Compute hr\_ratio, clipped to $[0.3, 1.2]$. Values below 0.80 indicate chronotropic incompetence.
\end{enumerate}

\textbf{Generated code (simplified):}
{\small
\begin{verbatim}
hr_ratio = MaxHR / (220 - Age)
hr_ratio = hr_ratio.clip(0.3, 1.2)
\end{verbatim}
}

\textbf{Why this matters.}
A syntactic AutoFE method might discover MaxHR/Age or MaxHR $-$ Age through operator enumeration, but these lack clinical meaning. The specific formula MaxHR$/\!(220 - \text{Age})$ with the 0.80 threshold comes directly from cardiology expertise encoded in \textit{EXP\_05}. This demonstrates how expert knowledge guides the agent toward a \emph{domain-correct} normalization rather than an arbitrary transformation.

\subsection{Case 3: Financial Vulnerability Score (Credit)}
\label{subsec:case3}

\textbf{Feature:} \texttt{financial\_vulnerability\_score} --- a 0--5 composite score capturing multi-dimensional financial fragility.

\textbf{Knowledge assets used:}
\begin{itemize}
    \item \textit{IND\_05}: Insufficient savings ($<$100 or unknown) indicates lack of financial buffer.
    \item \textit{IND\_09}: No known property indicates lack of collateral.
    \item \textit{IND\_11}: Non-owner housing (rent/free) implies ongoing cost pressure.
    \item \textit{RULE\_003}: Simultaneous no-savings, no-property, and renting yields 80\% default rate (vs.\ 30\% average) --- a triple-vulnerability with multiplicative interaction.
\end{itemize}

\textbf{Reasoning chain:}
\begin{enumerate}
    \item From \textit{IND\_05}: assign +1 if savings $<$100 or unknown.
    \item From \textit{IND\_09}: assign +1 if no known property; +0.5 if only car.
    \item From \textit{IND\_11}: assign +1 if renting or living for free.
    \item From \textit{RULE\_003}: assign +2 if \emph{all three} conditions are simultaneously met, capturing the non-linear interaction.
\end{enumerate}

\textbf{Generated code (simplified):}
{\small
\begin{verbatim}
score  = (savings < 100 or unknown)
score += (no_known_property)
score += (housing in {rent, free})
if all_three:
    score += 2  # RULE_003 penalty
\end{verbatim}
}

\textbf{Why this matters.}
The triple-vulnerability penalty (\textit{RULE\_003}) reflects a domain insight that financial fragility compounds super-additively: a borrower who lacks savings, property, \emph{and} stable housing is far riskier than individual factors suggest. Discovering this three-way interaction through exhaustive search over 20 features is combinatorially infeasible without guidance. KnowFeat generates it directly because \textit{RULE\_003} explicitly encodes the pattern.

These examples demonstrate three capabilities that distinguish KnowFeat from existing methods: (1)~\emph{multi-source fusion} --- combining indicators, rules, and expert opinions into a single coherent feature; (2)~\emph{domain-correct transformations} --- applying clinically or financially appropriate formulas rather than arbitrary operators; and (3)~\emph{non-linear interaction encoding} --- capturing super-additive risk combinations that are infeasible to discover through exhaustive search. Every feature includes a complete provenance chain linking each computation step to specific knowledge assets.
