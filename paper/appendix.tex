\section{Domain Knowledge and Verification Statistics}
\label{sec:appendix_knowledge}

This appendix illustrates the five knowledge types for the SimECNY AML dataset ($\sim$200K digital yuan transactions). One example per type is shown; similar structured knowledge is compiled for all types (38 indicators, 15 rules, 12 expert opinions, 309 court documents).

\smallskip
\noindent\textbf{(1) Schema Metadata.}
Column names, data types, and basic statistics extracted from the transaction data. Example fields include \texttt{amount} (numeric), \texttt{wallet\_type} (categorical, 4 types: anonymous, personal, enterprise, merchant), \texttt{hour} (numeric, 0--23), \texttt{src}/\texttt{dst} (wallet identifiers), and \texttt{transaction\_mode} (8 categories).

\smallskip
\noindent\textbf{(2) Risk Indicator} [IND\_05]:
Dimension: transaction behavior anomaly. Field: single-day transaction count. Accounts exceeding regulatory daily thresholds indicate potential money mule activity.

\smallskip
\noindent\textbf{(3) Detection Rule} [RULE\_006]:
\emph{Scatter-in, gather-out.} Logic: daily incoming count $\geq$ 20 AND daily amount $\geq$ 1{,}000{,}000, with high incoming but low outgoing count. Python hint: group by \texttt{(src, date)}, filter accounts with many small inflows and few large outflows.

\smallskip
\noindent\textbf{(4) Expert Opinion} [EXP]:
Online ``running-score'' laundering: anonymous wallet $\to$ real-name wallet $\to$ bank account chain transfers after midnight. Amounts 300--5{,}000 yuan, sustained 10--30 days, daily volume at wallet limits.

\smallskip
\noindent\textbf{(5) Court Document Evidence} [CASE]:
Criminal judgment on concealing proceeds. Pattern: digital yuan wallets across 6 banks creating a multi-layer fund channeling network via intermediary wallets and corporate-to-personal conversion.

\smallskip
\noindent\textbf{Verification Statistics.}
On SimECNY, KnowFeat generates 52 candidates across 4 rounds: 47 pass L1 (90\%), 31 pass L2 (60\%), and 18 pass L3 (35\%), with progressive filtering saving $\sim$50 minutes of L3 training. The per-round breakdown is: Round~1 produces 18 candidates (5 accepted), Round~2 produces 16 (6 accepted), Round~3 produces 11 (5 accepted), and Round~4 produces 7 (2 accepted). The declining candidate count reflects failure memory effectiveness: as more rejected ideas accumulate, the agent avoids previously explored directions and converges faster. Forward selection recovers 3 additional features from L2-passed but L3-failed candidates across all rounds, contributing +0.4pp to the final Recall improvement.

\section{Practical Considerations}
\label{sec:practical}

We discuss practical aspects of deploying KnowFeat based on our experience with the SimECNY dataset.

\textbf{Computational Cost.}
The full pipeline takes $\sim$3.2 hours for 4 rounds on SimECNY (52 candidates, 18 accepted). L3 model evaluation dominates at 41\% of total time ($\sim$2.5 min per candidate), followed by LLM reasoning at 23\% ($\sim$52 sec per candidate). Progressive filtering saves $\sim$53 minutes by rejecting 21 candidates at L1/L2 before expensive L3 evaluation. The LLM API cost is approximately \$2.80 for the full run (DeepSeek-V4-0324-Flash). Importantly, this is a one-time setup: at inference, only the generated Python code runs, adding $<$50ms per 200K-transaction batch.

\textbf{Compliance Integration.}
Provenance cards map directly to existing AML compliance review processes. The knowledge asset identifiers (e.g., RULE\_006, IND\_15) reference the same regulatory documents that compliance officers work with. Domain experts from the Postal Savings Bank of China reported that the structured format reduced feature review time from 2--3 hours to 15--30 minutes per feature, as the reasoning chain eliminates the need to reconstruct the designer's rationale. This directly supports Article~32 of China's Anti-Money Laundering Law (2024 revision), which mandates documenting the basis for suspicious transaction reporting.

\textbf{Lessons Learned.}
Three insights emerged: (1)~\emph{Knowledge curation cost varies by domain}: the full AML knowledge base (38 indicators, 15 rules, 12 expert opinions, 309 court documents) required $\sim$3 person-weeks, where the court document extraction was semi-automated via an LLM-based key-clue extractor and the remaining types were manually compiled from regulatory guidelines. In contrast, the simplified knowledge bases for public datasets (10--14 indicators, 8--10 rules, 6--8 expert consensus items per dataset) were constructed in $\sim$2--4 hours each by extracting domain facts from authoritative medical guidelines, financial regulations, and census documentation with LLM assistance. This suggests that knowledge curation scales reasonably for well-documented domains. (2)~\emph{Verification thresholds require domain calibration}: the L3 acceptance criteria (e.g., $\Delta$Recall $> 0$ with Precision $\geq 90\%$) must be set with domain stakeholders. (3)~\emph{Feature maintenance is ongoing}: regulatory requirements evolve, and a periodic refresh cycle (e.g., quarterly) would be necessary in production.

\textbf{Adaptability to New Domains.}
KnowFeat's design is domain-agnostic: the five knowledge types serve as a general template that can be instantiated for any tabular classification task. Our public dataset experiments confirm this---we constructed knowledge bases for seven domains using publicly available guidelines. The key requirement is that a domain expert can articulate risk indicators, detection rules, and expert heuristics in structured natural language; the LLM agent handles translation to executable code. The verification pipeline (L1--L3) requires no domain-specific configuration beyond the target metric, and the semantic dimension decomposition can be adapted to any feature space.
