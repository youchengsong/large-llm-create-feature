\section{Experiments}
\label{sec:experiments}

We evaluate KnowFeat on both public tabular benchmarks and a realistic anti-money laundering (AML) dataset. Our experiments aim to answer four research questions:
\begin{itemize}
    \item \textbf{RQ1}: Does KnowFeat improve predictive performance on public datasets?
    \item \textbf{RQ2}: How does KnowFeat perform on a realistic AML task with severe class imbalance?
    \item \textbf{RQ3}: What is the contribution of domain knowledge?
    \item \textbf{RQ4}: How does KnowFeat balance feature quantity vs.\ quality, and do verified features generalize?
\end{itemize}

\subsection{Experimental Setup}
\label{subsec:setup}

\subsubsection{Datasets}

The seven public datasets are standard tabular classification benchmarks obtained via the OpenML Python API~\cite{vanschoren2014openml}. SimECNY is a synthetic AML benchmark calibrated against real digital currency (e-CNY) transaction patterns from the Postal Savings Bank of China. Its 93 baseline features, transaction topology, and class distribution (2.24\% positive rate, 4{,}484 suspicious among 200{,}000 transactions) faithfully reflect production AML systems. Due to financial privacy regulations, high-fidelity simulation is standard practice in AML research~\cite{weber2019anti}. Importantly, the domain knowledge base (38 indicators, 15 rules, 12 expert opinions, 309 court documents) is derived entirely from real regulatory guidelines, compliance manuals, expert interviews, and publicly available court judgments.

For the seven public datasets, we also construct simplified knowledge bases with three types: risk indicators (IND), detection rules (RULE), and expert consensus (EXP), compiled from medical guidelines, financial regulations, and census documentation. Table~\ref{tab:ablation} reports the exact composition per dataset (e.g., heart: 12 IND, 10 RULE, 8 EXP). Although simpler than the AML hierarchy, these knowledge bases consistently improve over the schema-only baseline (Section~\ref{subsec:rq3}).

\subsubsection{Baselines}
We compare against seven baselines:
\begin{itemize}
    \item \textbf{No-FE}: XGBoost~\cite{chen2016xgboost} on original features.
    \item \textbf{OpenFE}~\cite{zhang2023openfe}: Transformation-based AutoFE with LightGBM~\cite{ke2017lightgbm}-based selection.
    \item \textbf{AutoFeat}~\cite{horn2019autofeat}: Polynomial feature generation with L1 selection.
    \item \textbf{CAAFE}~\cite{hollmann2023caafe}: LLM-based iterative feature generation with logistic regression feedback.
    \item \textbf{FeatLLM}~\cite{han2024featllm}: LLM-based rule extraction and binary feature generation.
    \item \textbf{LLM-FE}~\cite{abhyankar2025llmfe}: LLM-based evolutionary feature optimization that iteratively generates and refines features using structured prompts.
    \item \textbf{OCTree}~\cite{nam2024octree}: LLM-based feature generation guided by decision tree reasoning.
\end{itemize}

\subsubsection{Evaluation Protocol}
All methods are evaluated using XGBoost~\cite{chen2016xgboost} (n\_estimators=200, max\_depth=6, learning\_rate=0.1) with stratified 80/20 train-test splits across 5 random seeds. We use AUC as the primary metric for all datasets, as it is threshold-independent and more robust than accuracy for datasets with varying class distributions. For SimECNY, we additionally report Recall, Precision, and F1 with scale\_pos\_weight=auto ($\approx$43.6) to handle class imbalance. All baselines are reproduced using our unified evaluation protocol to ensure fair comparison.

KnowFeat's 18 features improve Recall by +2.1pp over No-FE (0.9871 vs.\ 0.9663) and F1 by +1.5pp (0.9863 vs.\ 0.9713). To assess statistical significance, we conduct a Wilcoxon signed-rank test on per-seed F1 scores between KnowFeat and the second-best method (LLM-FE): the difference is significant ($p < 0.05$). The contrast between verified and unverified features is striking: KnowFeat's 18 verified features improve F1 by +1.5pp, while FeatLLM's 1{,}031 unverified features \emph{decrease} F1 by $-$0.4pp.

To verify robustness, we re-evaluate all methods with scale\_pos\_weight=1 (no class balancing). KnowFeat remains the only method that outperforms No-FE (F1 0.9812), confirming that the 18 features encode genuine discriminative signal independent of class reweighting.

\textbf{Analysis by semantic dimension.}
The 18 accepted features span all four semantic dimensions defined in Section~\ref{subsec:search}: 6 in Amount \& Frequency, 5 in Time \& Geography, 4 in Behavior Sequence, and 3 in Entity Association. SHAP analysis on the final model reveals that Entity Association features contribute the highest mean absolute SHAP values despite being fewest in number, indicating that network topology features (e.g., fan-in/fan-out ratios, counterparty diversity) carry particularly strong signals for AML detection. Amount \& Frequency features collectively rank second, consistent with domain knowledge that transaction amount thresholds and velocity patterns are primary regulatory red flags. The balanced coverage across dimensions, enabled by SHAP-guided budget reallocation, is important: removing any single dimension's features degrades Recall by 0.3--0.8pp, confirming that the dimensions capture complementary signals.

\subsection{Representative Feature Analysis}
\label{sec:case_study}

We present two representative cases from the SimECNY AML dataset, highlighting multi-source knowledge fusion and cross-dimensional interaction. Table~\ref{tab:provenance} shows the complete provenance cards for both features.

\textbf{Case 1: Fan-In/Fan-Out Ratio (Network Topology).}
This feature fuses four knowledge assets spanning three types (rules, patterns, indicators) to produce a topology-aware asymmetry score. The key insight from RULE\_006 and RULE\_013 is that both scatter-in/gather-out layering and pyramid fund networks manifest as fan-in/fan-out asymmetry. PAT\_A03 further confirms that money mule wallets typically exhibit fan-in $\gg$ fan-out. IND\_15 adds a weighting factor based on abnormal transaction modes (many-to-many, one-to-many), amplifying the signal for wallets with suspicious mode distributions. No syntactic method would produce this feature, as it requires understanding that directional imbalance combined with abnormal mode prevalence characterizes money mule behavior.

\textbf{Case 2: Cross-Dimensional Risk Interaction.}
This feature demonstrates \emph{cross-dimensional interaction}: geographic context (account metadata) combined with temporal patterns (transaction logs), guided by expert knowledge. The critical insight from EXP\_05 is that neither geographic risk nor off-hour activity alone is sufficient evidence; only their conjunction indicates cross-border laundering. The multiplicative form encodes this domain constraint exactly: border-region accounts with normal trading hours score zero, as do off-hour traders in non-border regions.

Both cases illustrate capabilities that syntactic methods cannot replicate. The provenance cards in Table~\ref{tab:provenance} trace every design decision to specific knowledge assets, providing the provenance trail required for regulatory review.

\subsection{RQ3: Ablation Study}
\label{subsec:rq3}

To quantify the contribution of domain knowledge, we compare the \textit{schema\_only} variant (schema metadata only) against the \textit{full} variant (all five knowledge types). Results on public datasets are shown in Table~\ref{tab:ablation}.

On diabetes, schema-only generates \emph{zero} features passing L3, while full knowledge produces 24 features (+0.016 AUC). On five of six remaining datasets, the full variant outperforms schema-only (+0.001 to +0.012 AUC). On blood\_transfusion, both variants generate 12 features but differ in quality, confirming that knowledge improves feature \emph{quality}, not just quantity. On SimECNY, the gap is largest: schema-only generates 3 features (+0.3pp Recall) vs.\ full knowledge with 18 features (+2.1pp Recall), confirming that domain-specific knowledge assets are the primary driver.

\textbf{Which knowledge types matter most?}
On SimECNY, we further ablate individual knowledge types by removing one type at a time from the full configuration. Removing court document evidence causes the largest drop ($-$0.9pp Recall), as case-derived patterns such as pyramid fund networks and multi-layer channeling structures provide concrete, legally validated signals that the LLM cannot infer from other sources. Removing detection rules ranks second ($-$0.6pp Recall), reflecting their role in encoding precise operational logic (e.g., scatter-in/gather-out thresholds). Removing risk indicators or expert opinions each causes moderate drops ($-$0.3pp to $-$0.4pp Recall). These results suggest that more specific, concrete knowledge types contribute disproportionately, supporting our hierarchical design where general metadata serves as a foundation and domain-specific evidence provides the strongest signals.

On SimECNY, KnowFeat's 18 verified features improve F1 by +1.5pp, while FeatLLM's 1{,}031 unverified features decrease F1 by $-$0.4pp. This confirms that the three-stage verification pipeline is critical for ensuring genuine predictive value. OpenFE's 30 additional syntactic features also hurt on SimECNY, as domain-blind transformations introduce redundancy in a high-dimensional (93-feature) setting.

Beyond quantity and quality, we further examine whether KnowFeat's verified features generalize across models and remain stable across runs.

\textbf{Cross-model validation.} To verify that accepted features are not XGBoost-specific, we evaluate KnowFeat-generated features with LightGBM~\cite{ke2017lightgbm} and CatBoost. On credit\_g, adult, and SimECNY, KnowFeat features improve LightGBM AUC by +0.015, +0.005, and +0.0003 respectively, and CatBoost AUC by +0.012, +0.003, and +0.0002, comparable to XGBoost gains, confirming that L2's model-independent filters (IV, KS) produce transferable signals.

\textbf{Generation stability.} We run 3 independent end-to-end executions on adult (DeepSeek-V4-0324-Flash, temperature=0). The accepted feature counts (44, 46, 43) and final AUC (0.9301, 0.9298, 0.9305; std $<$ 0.001) are highly consistent despite different feature names/code, demonstrating \emph{functional reproducibility} through the verification pipeline.
