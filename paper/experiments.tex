\section{Experiments}
\label{sec:experiments}

We evaluate KnowFeat on both public tabular benchmarks and a real-world anti-money laundering (AML) dataset. Our experiments aim to answer four research questions:
\begin{itemize}
    \item \textbf{RQ1}: Does KnowFeat improve predictive performance on public datasets?
    \item \textbf{RQ2}: How does KnowFeat perform on a real-world AML task with severe class imbalance?
    \item \textbf{RQ3}: What is the contribution of domain knowledge?
    \item \textbf{RQ4}: How does KnowFeat balance feature quantity vs.\ quality?
\end{itemize}

\subsection{Experimental Setup}
\label{subsec:setup}

SimECNY is a real-world digital currency transaction dataset containing 200,000 transactions with 93 baseline features and 4,484 positive (suspicious) samples, representing a realistic AML scenario with severe class imbalance (2.24\% positive rate).

\subsubsection{Baselines}
We compare against six baselines:
\begin{itemize}
    \item \textbf{No-FE}: XGBoost~\cite{chen2016xgboost} on original features.
    \item \textbf{OpenFE}~\cite{zhang2023openfe}: Transformation-based AutoFE with LightGBM~\cite{ke2017lightgbm}-based selection.
    \item \textbf{AutoFeat}~\cite{horn2019autofeat}: Polynomial feature generation with L1 selection.
    \item \textbf{CAAFE}~\cite{hollmann2023caafe}: LLM-based iterative feature generation with logistic regression feedback.
    \item \textbf{FeatLLM}~\cite{han2024featllm}: LLM-based rule extraction and binary feature generation.
    \item \textbf{LLM-FE}~\cite{abhyankar2025llmfe}: Evolutionary LLM feature optimization with structured prompts.
\end{itemize}

\subsubsection{Evaluation Protocol}
All methods are evaluated using XGBoost~\cite{chen2016xgboost} (n\_estimators=200, max\_depth=6, learning\_rate=0.1) with stratified 80/20 train-test splits across 5 random seeds. We use AUC as the primary metric for all datasets. For SimECNY, we additionally report Recall, Precision, and F1 with scale\_pos\_weight=auto ($\approx$43.6) to handle class imbalance. All baselines are reproduced using our unified evaluation protocol to ensure fair comparison.

\subsubsection{Computational Cost}
KnowFeat's cost is dominated by LLM API calls and L3 model evaluation. On public datasets, the average wall-clock time is 15--40 minutes per dataset (DeepSeek-V3 API), with an average API cost of \$2.40 per run. L3 verification accounts for $\sim$60\% of total time. On SimECNY (200K samples), a full run takes $\sim$2 hours. By comparison, LLM-FE requires 3--8 hours due to its evolutionary search, while OpenFE completes in 5--15 minutes but generates only syntactic transformations.

KnowFeat achieves the best performance on 4 of 7 datasets (credit\_g, blood\_transfusion, breast\_w, adult) and ranks second on 2 datasets (diabetes, heart). Notably, LLM-FE underperforms No-FE on two datasets, suggesting that evolutionary optimization without structured knowledge and multi-stage verification is insufficient.

\emph{Takeaway: KnowFeat achieves the best average rank (1.4) with the most consistent performance across diverse domains, without requiring dataset-specific tuning.}

KnowFeat's 18 domain-knowledge features yield substantial improvements: Recall improves by +2.1pp over No-FE (0.987 vs.\ 0.966), F1 by +1.5pp (0.986 vs.\ 0.971), and AUC reaches 0.9999. LLM-FE achieves the second-best F1 (0.973) with only 1 additional feature, but KnowFeat's margin over LLM-FE remains large (+1.3pp F1, +1.7pp Recall). FeatLLM adds 1,031 features yet achieves the \emph{worst} performance, demonstrating that unverified feature quantity degrades rather than improves models.

\textbf{Robustness check.} We re-evaluate with scale\_pos\_weight=1 (no class balancing). KnowFeat remains the clear winner (F1 0.981) and is the \emph{only} method that outperforms No-FE, confirming that the 18 features encode genuine discriminative signal independent of class reweighting.

\emph{Takeaway: On the real-world AML dataset, KnowFeat's 18 verified features outperform 1{,}031 unverified features from FeatLLM, demonstrating that knowledge-guided quality dominates brute-force quantity.}

\emph{Takeaway: Domain knowledge is essential---without it, the LLM generates zero useful features on one dataset and consistently fewer/weaker features on others.}
