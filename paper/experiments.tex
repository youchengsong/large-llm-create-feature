\section{Experiments}
\label{sec:experiments}

We evaluate KnowFeat on both public tabular benchmarks and a real-world anti-money laundering dataset. Our experiments aim to answer four research questions:
\begin{itemize}
    \item \textbf{RQ1}: Does KnowFeat improve predictive performance compared to existing AutoFE and LLM-based methods?
    \item \textbf{RQ2}: How does KnowFeat perform on a real-world AML task with severe class imbalance?
    \item \textbf{RQ3}: What is the contribution of each knowledge level? (Ablation study)
    \item \textbf{RQ4}: How does KnowFeat balance feature quantity vs.\ quality?
\end{itemize}

\label{subsec:setup}

The six public datasets are standard tabular benchmarks from OpenML, covering diverse domains (finance, healthcare, marketing). SimECNY is a real-world digital currency transaction dataset containing 200,000 transactions with 93 baseline features and 4,484 positive (suspicious) samples, representing a realistic AML detection scenario with severe class imbalance (2.24\% positive rate).

\subsubsection{Baselines}
We compare KnowFeat against five baselines:
\begin{itemize}
    \item \textbf{No-FE}: XGBoost trained on original features without any feature engineering.
    \item \textbf{OpenFE}~\cite{zhang2024openfe}: State-of-the-art transformation-based AutoFE that searches over operator-operand combinations.
    \item \textbf{AutoFeat}~\cite{horn2020set}: Polynomial and interaction feature generation with L1 selection.
    \item \textbf{CAAFE}~\cite{hollmann2024llmsgeneratefinanciallyrelevantfeatures}: LLM-based iterative feature generation with logistic regression feedback.
    \item \textbf{FeatLLM}~\cite{han2024featllm}: LLM-based rule extraction and binary feature generation.
\end{itemize}

\subsubsection{Evaluation Protocol}
All methods are evaluated using XGBoost (n\_estimators=200, max\_depth=6, learning\_rate=0.1) with stratified 80/20 train-test splits across 5 random seeds. For public datasets, the primary metric is AUC. For the AML dataset, we report Recall, Precision, F1, and AUC, with scale\_pos\_weight=auto to handle class imbalance. We additionally report results with scale\_pos\_weight=1 (no class balancing) to better differentiate methods under challenging conditions.

CAAFE and FeatLLM perform close to or below the No-FE baseline on most datasets, suggesting that their generated features often introduce noise rather than signal. This is consistent with their lack of rigorous verification: without L2 and L3 filtering, low-quality features dilute the model's predictive power.

\subsection{RQ3: Ablation Study}
\label{subsec:rq3}

To quantify the contribution of domain knowledge, we compare the \textit{schema\_only} variant (Level 0: no domain knowledge, only dataset metadata) against the \textit{full} variant (all knowledge levels). Results are shown in Table~\ref{tab:ablation}.

\small
\renewcommand{\arraystretch}{1.2}

\begin{tabular}{l c c c}

\textbf{Dataset} & \textbf{schema\_only} & \textbf{full} & $\boldsymbol{\Delta}$ \\
\hline

diabetes      & --- (0 feat.) & .8190{\scriptsize$\pm$.032} & --- \\
\hline
\end{tabular}
\end{table}

The results reveal several important findings:

\textbf{Knowledge drives feature generation.} On the diabetes dataset, the schema-only variant generates \emph{zero} features that pass the L3 verification---the LLM cannot create useful features from column names alone without domain understanding. With full knowledge, KnowFeat generates 24 accepted features and improves AUC by +0.016 over No-FE.

\textbf{Knowledge improves feature quality.} On four of five remaining datasets, the full variant outperforms schema\_only, with gains ranging from +0.003 (bank\_marketing) to +0.012 (blood\_transfusion). On blood\_transfusion, both variants generate 12 features, indicating that the improvement comes from feature \emph{quality}, not quantity---domain knowledge guides the agent toward more predictive transformations. The largest gain (+0.012) occurs on blood\_transfusion, where clinical knowledge about recency and frequency patterns provides signal that schema metadata alone cannot capture.

\textbf{breast\_w exception.} On breast\_w, schema\_only slightly outperforms full ($-$0.001 AUC). We attribute this to the dataset's near-ceiling baseline (AUC $>$ 0.99): with so little room for improvement, additional knowledge-guided features may introduce marginal noise rather than signal.

FeatLLM generates by far the most features (98--1,124), yet achieves the worst or near-worst performance on most datasets. On SimECNY, the contrast is particularly stark: KnowFeat adds only 2 features (both verified to improve recall) while FeatLLM adds 1,031 features (unverified), yet KnowFeat achieves higher F1 and Recall. This demonstrates the effectiveness of quality-over-quantity feature engineering.

\subsection{Provenance and Interpretability}
\label{subsec:provenance}

A distinctive advantage of KnowFeat is that every generated feature comes with a provenance card. Figure~\ref{fig:provenance} shows an example provenance card for a feature generated on the AML dataset.

\begin{figure}[t]
    \centering
    \fbox{\parbox{0.9\columnwidth}{\centering\vspace{1.5cm}\textit{[Provenance card example placeholder]}\vspace{1.5cm}}}
    \caption{Example provenance card for a KnowFeat-generated feature, showing the knowledge assets (RULE\_003, IND\_12), reasoning chain, and computation steps.}
    \label{fig:provenance}

Each provenance card includes: (1) the knowledge assets that inspired the feature, referenced by ID; (2) a structured reasoning chain explaining \emph{why} the feature is relevant; and (3) the computation steps from raw fields to the final value. This level of traceability is essential for deployment in regulated industries where model features must be auditable and explainable to compliance officers and regulators.
