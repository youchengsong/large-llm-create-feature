\section{Experiments}
\label{sec:experiments}

We evaluate KnowFeat on both public tabular benchmarks and a real-world anti-money laundering (AML) dataset. Our experiments aim to answer four research questions:
\begin{itemize}
    \item \textbf{RQ1}: Does KnowFeat improve predictive performance on public datasets?
    \item \textbf{RQ2}: How does KnowFeat perform on a real-world AML task with severe class imbalance?
    \item \textbf{RQ3}: What is the contribution of domain knowledge? (Ablation study)
    \item \textbf{RQ4}: How does KnowFeat balance feature quantity vs.\ quality?
\end{itemize}

\subsection{Experimental Setup}
\label{subsec:setup}

\subsubsection{Baselines}
We compare against six baselines:
\begin{itemize}
    \item \textbf{No-FE}: XGBoost~\cite{chen2016xgboost} on original features.
    \item \textbf{OpenFE}~\cite{zhang2023openfe}: Transformation-based AutoFE with LightGBM~\cite{ke2017lightgbm}-based selection.
    \item \textbf{AutoFeat}~\cite{horn2019autofeat}: Polynomial feature generation with L1 selection.
    \item \textbf{CAAFE}~\cite{hollmann2023caafe}: LLM-based iterative feature generation with logistic regression feedback.
    \item \textbf{FeatLLM}~\cite{han2024featllm}: LLM-based rule extraction and binary feature generation.
    \item \textbf{LLM-FE}~\cite{abhyankar2025llmfe}: LLM-based evolutionary feature optimization that iteratively generates and refines features using structured prompts.
\end{itemize}

\subsubsection{Evaluation Protocol}
All methods are evaluated using XGBoost~\cite{chen2016xgboost} (n\_estimators=200, max\_depth=6, learning\_rate=0.1) with stratified 80/20 train-test splits across 5 random seeds. We use AUC as the primary metric for all datasets, as it is threshold-independent and more robust than accuracy for datasets with varying class distributions. For SimECNY, we additionally report Recall, Precision, and F1 with scale\_pos\_weight=auto ($\approx$43.6) to handle class imbalance. All baselines are reproduced using our unified evaluation protocol to ensure fair comparison.

KnowFeat's 18 domain-knowledge features yield substantial improvements: Recall improves by +2.1pp over No-FE (0.9871 vs.\ 0.9663), F1 by +1.5pp (0.9863 vs.\ 0.9713), and AUC reaches 0.9999. LLM-FE achieves the second-best F1 (0.9728) with only 1 additional feature, but KnowFeat's margin over LLM-FE remains large (+1.4pp F1, +1.7pp Recall). KnowFeat suffers the smallest Recall drop when switching from spw=auto to spw=1 ($\Delta = -$1.9pp), while FeatLLM drops the most ($\Delta = -$3.3pp). This confirms that KnowFeat's 18 features encode genuine discriminative signal that does not depend on class reweighting.

\textbf{Knowledge drives feature generation.} On the diabetes dataset, the schema-only variant generates \emph{zero} features that pass L3 verification. With full knowledge, KnowFeat generates 24 accepted features and improves AUC by +0.016 over No-FE.

\textbf{Knowledge improves feature quality.} On five of the six remaining datasets, the full variant outperforms schema\_only, with gains ranging from +0.001 (adult) to +0.012 (blood\_transfusion). On blood\_transfusion, both variants generate 12 features, indicating that the improvement comes from feature \emph{quality}, not quantity.

\textbf{SimECNY ablation.} On the AML dataset, domain knowledge is critical: schema\_only generates only 3 features (+0.3pp Recall over No-FE), while the full knowledge hierarchy generates 18 features (+2.1pp Recall). The gap between schema\_only and full (+1.8pp Recall, +1.4pp F1) confirms that the AML-specific knowledge assets (detection rules, behavioral patterns, expert opinions) are the primary driver of KnowFeat's advantage.

\subsection{Provenance and Interpretability}
\label{subsec:provenance}

Every KnowFeat-generated feature includes a provenance card recording: (1) the knowledge assets that inspired it; (2) a reasoning chain explaining \emph{why} the feature is relevant; and (3) the computation steps from raw fields to the final value. This traceability is essential for deployment in regulated industries. We illustrate this capability through detailed case studies in Section~\ref{sec:case_study}.
