大模型驱动的自动特征工程系统

基于LLM Agent的反洗钱特征自动生成、验证与评估系统设计文档

项目背景：本系统面向数字人民币反洗钱场景，利用大语言模型（LLM）自主生成检测特征代码，通过多层级验证确保特征质量，最终提升洗钱交易检测的召回率和精确率。系统参考了309份数字人民币相关裁判文书和专家访谈知识。
单Agent系统
基于ReAct范式的自主特征工程Agent，通过Tool Use循环完成知识检索、特征生成、沙箱验证、质量评估的全流程。
多Agent系统
Generator + Critic + Validator三组件协作，通过对抗审查确保特征鲁棒性，经修改循环优化后通过统计验证。
三级验证管道
L1沙箱执行验证代码正确性，L2统计验证（IV/KS/冗余度），L3模型验证（XGBoost 5-fold CV增量评估）。
领域知识驱动
整合309份裁判文书、专家访谈、38个风险指标、15条检测规则，为LLM提供充分的反洗钱领域上下文。

检测规则 (detection_rules) 15条规则

15条形式化检测规则，包含一阶逻辑表达式和Python实现示例。例如：

# RULE_002: 休眠账户突然激活 — 开户后>=90天无交易后突然出现交易 def feature_dormant_account_activation(open_df, tx_df, close_df): import pandas as pd open_df = open_df.copy() open_df["wallet_open_date"] = pd.to_datetime(open_df["wallet_open_date"]) first_tx = tx_df[["src", "timestamp"]].groupby("src")["timestamp"].min() merged = open_df.merge(first_tx, left_on="wallet_id", right_index=True) merged["dormant_days"] = (merged["timestamp"] - merged["wallet_open_date"]).dt.days merged["is_dormant_activated"] = (merged["dormant_days"] >= 90).astype(int) return merged[["wallet_id", "is_dormant_activated"]]

Agent架构设计

ReAct循环架构

单Agent系统基于ReAct范式Reasoning + Acting: 大语言模型交替进行推理和行动，通过Tool Use自主完成特征工程全流程。Agent在每一步先进行思考（Thought），然后选择调用一个工具（Action），最后根据观察结果（Observation）决定下一步。

工具详细说明

工具名功能输入参数调用时机
retrieve_knowledge 检索领域知识 knowledge_type: transaction_patterns / expert_interview / risk_indicators / detection_rules 初始阶段，了解洗钱模式
inspect_schema 查看数据表结构 table: open_df / tx_df / close_df 初始阶段，了解可用字段
generate_feature 生成特征代码 feature_name, dimension, code, explanation, reasoning 设计好特征后提交代码
execute_sandbox 沙箱验证代码 feature_name, code 生成代码后立即验证
evaluate_feature L2+L3评估 feature_name 沙箱通过后评估质量
finish 结束生成过程 reason, summary 达到目标或维度覆盖完成

决策逻辑

Agent的决策由LLM自主完成，系统通过以下机制引导：

  • 初始探索阶段
    Agent倾向于先调用 retrieve_knowledge 和 inspect_schema，建立对问题的理解。System Prompt建议"先检索领域知识和查看数据结构"。
  • 特征生成阶段
    基于知识和数据结构设计特征。Agent在Thought中推理特征的业务含义，然后调用 generate_feature + execute_sandbox + evaluate_feature。
  • 反馈调整阶段
    如果特征被拒绝（L2/L3未通过），Agent收到详细反馈信息（IV值、冗余度等），自主决定修复代码或换方向。
  • 终止判断
    满足以下任一条件时终止：(1) 接受特征数达到 max_features; (2) Agent自主调用finish; (3) 步数达到 max_steps=50。

关键配置参数

参数默认值说明
max_steps50最大推理步数
max_features20目标特征数量
temperature0.7LLM生成温度
modeldeepseek-chat使用的LLM模型

Generator + Critic + Validator 架构

多Agent系统将特征工程分解为三个专业角色，通过对抗式协作提升特征质量。

Generator Agent 详解

角色定位：专业反洗钱特征工程专家，负责设计有区分力的特征并编写完整Python代码。根据Critic反馈迭代优化。

System Prompt 设计要点

  • 明确函数签名要求：def feature_xxx(open_df, tx_df, close_df) -> pd.DataFrame
  • 禁止使用标签列（防止数据泄露）
  • 要求处理空值和除零错误
  • import语句放在函数内部（沙箱隔离）
  • 强调可解释性：特征需向监管人员解释
  • 输出严格JSON格式，包含feature_name, dimension, code, explanation, reasoning

上下文管理

每轮生成时，Generator收到的prompt包含：数据Schema、领域知识（截断至3000字符）、已接受特征列表（避免重复）、最近被拒绝特征（避免相似方向）。连续失败3次后，系统重置Generator上下文防止陷入循环。

Critic Agent 详解

角色定位：同时具备洗钱者视角和审计员视角，进行对抗性审查。使用较低温度（0.3）确保评估稳定性。

四维审查标准

1. 鲁棒性
  • 是否依赖容易伪造的信号？
  • 洗钱者能否简单改变行为绕过？
  • 对正常用户行为变化是否过度敏感？
2. 可部署性
  • 是否需要全局统计信息？
  • 计算复杂度是否合理？
  • 是否依赖线上不可获取的字段？
3. 冗余性
  • 是否测量了与已有特征相同的信号？
  • 能否通过已有特征简单组合得到？
4. 可解释性
  • 业务含义是否清晰？
  • 触发高风险值时能否给出解释？

Critic输出格式

{ "verdict": "pass" | "revise" | "reject", "robustness_score": 1-5, // 鲁棒性评分 "deployability_score": 1-5, // 可部署性评分 "redundancy_risk": "low/medium/high", // 冗余风险 "explainability_score": 1-5, // 可解释性评分 "issues": ["问题1", "问题2"], "suggestions": ["改进建议1", "改进建议2"], "evasion_scenario": "洗钱者可能如何规避的场景描述" }

Validator 组件详解

Validator是确定性组件（非LLM），执行代码验证和统计评估：

  1. validate_code(code)：调用L1沙箱验证，返回 (feature_df, error)
  2. evaluate_quality(feature_df, name)：合并特征到交易表，执行L2统计检验和L3模型增量评估

修改循环机制

当Critic返回 verdict: "revise" 时，系统进入修改循环：

  1. 将Critic的issues、suggestions和evasion_scenario传给Generator
  2. Generator输出修改后的完整代码（JSON格式）
  3. 重新沙箱验证修改后的代码
  4. 重新Critic审查修改后的特征
  5. 最多循环 max_revisions=2 次

维度轮换策略

系统预定义6个探索维度，按顺序轮换：

dimensions = ["时间模式", "金额模式", "网络结构", "账户行为", "设备/环境", ""] # 最后一个空字符串表示Generator自由选择维度

验证管道 (L1 / L2 / L3)

三级验证管道确保生成的特征在代码正确性、统计区分力和模型增量三个层面都满足要求。

L1: 沙箱执行验证 代码正确性

L1验证确保特征代码能够正确执行并产生有效输出。在隔离的子进程中运行，防止恶意代码影响主系统。

验证流程

  • AST安全检查
    使用Python AST解析代码，禁止导入危险模块（os, sys, subprocess等），禁止调用危险内置函数（open, exec, eval等）。只允许导入pandas, numpy, scipy, sklearn。
  • 子进程隔离执行
    使用multiprocessing.Process在独立进程中执行代码，超时时间30秒。数据通过Parquet文件传递（缓存机制避免重复序列化）。
  • 输出格式验证
    验证返回值是否为pandas DataFrame，是否包含wallet_id或tx_id列，特征列是否为数值型，NaN比例是否低于50%，是否有至少2个唯一值。

L1检查清单

检查项条件失败后果
代码语法正确AST可解析直接拒绝
无危险导入只允许pandas/numpy/scipy/sklearn直接拒绝
无危险调用禁止open/exec/eval等直接拒绝

L2: 统计质量评估 IV + KS + 冗余度

Information Value (IV)

IV (Information Value) 计算公式
IV = Σi=1N (Good%i - Bad%i) × ln(Good%i / Bad%i)

其中：
  N = 分箱数（等频分箱，默认10个bin）
  Good%i = 第i个bin中正常样本数 / 总正常样本数
  Bad%i = 第i个bin中洗钱样本数 / 总洗钱样本数
  WOEi = ln(Good%i / Bad%i)（Evidence Weight）

IVi = (Good%i - Bad%i) × WOEi
def compute_iv(feature, label, n_bins=10): feat = feature.fillna(0) if feat.nunique() <= 2: binned = feat # 二值特征不分箱 else: binned = pd.qcut(feat, q=n_bins, duplicates="drop") # 等频分箱 total_good = (label == 0).sum() total_bad = (label == 1).sum() iv = 0.0 for bin_group in grouped: good_pct = max(good / total_good, 1e-10) # 平滑处理防止log(0) bad_pct = max(bad / total_bad, 1e-10) woe = np.log(good_pct / bad_pct) iv += (good_pct - bad_pct) * woe return iv
IV判读标准：IV < 0.02 无预测力 | 0.02-0.1 弱 | 0.1-0.3 中等 | 0.3-0.5 强 | >0.5 可疑（可能过拟合）。系统阈值：iv_min = 0.001（宽松设置，因数据极度不平衡）。

KS统计量 (Kolmogorov-Smirnov)

KS (Kolmogorov-Smirnov) 统计量
KS = maxx |Fpositive(x) - Fnegative(x)|

其中：
  Fpositive(x) = 洗钱样本中特征值 ≤ x 的比例（正样本CDF）
  Fnegative(x) = 正常样本中特征值 ≤ x 的比例（负样本CDF）
  KS值越大，表示特征对正负样本的区分度越好

实现优化：当唯一值 > 1000时，使用1000个百分位点近似
def compute_ks(feature, label): feat = feature.fillna(0).values pos = feat[label == 1] # 洗钱样本 neg = feat[label == 0] # 正常样本 all_vals = np.sort(np.unique(feat)) if len(all_vals) > 1000: all_vals = np.percentile(feat, np.linspace(0, 100, 1000)) pos_cdf = np.searchsorted(np.sort(pos), all_vals, side="right") / len(pos) neg_cdf = np.searchsorted(np.sort(neg), all_vals, side="right") / len(neg) return np.max(np.abs(pos_cdf - neg_cdf))

冗余度 (Redundancy)

冗余度计算
Redundancy = maxj |corr(new_feature, existing_featurej)|

其中：
  corr() 为Pearson相关系数
  遍历所有已有特征，取最大绝对相关系数
  无已有特征时返回0

L2通过条件

指标阈值含义
IV≥ 0.001特征对标签有最低预测力
KS≥ 0.001正负样本分布有最低差异
冗余度< 0.7与已有特征不高度相关
缺失率≤ 0.5不超过50%的缺失值
通过条件：四项指标同时满足才能进入L3评估。
L3: 模型增量评估 XGBoost 5-fold CV

XGBoost模型参数

参数值说明

Delta指标计算流程

增量评估 (Delta Metrics)
5-Fold StratifiedKFold CV:

对每个fold:
  1. 训练基线模型: M_base = XGBoost(X_existing[train], y[train])
  2. 训练增强模型: M_aug = XGBoost(X_existing + new_feature[train], y[train])
  3. 在训练集上找最优阈值: thr = argmax_t F1(y_train, prob_train >= t)
  4. 在验证集上应用阈值: y_pred = (prob_val >= thr)
  5. 计算各指标: F1, Recall, Precision

最终:
  delta_f1 = mean(aug_f1) - mean(base_f1)
  delta_recall = mean(aug_recall) - mean(base_recall)
  delta_precision = mean(aug_precision) - mean(base_precision)

阈值优化

F1最优阈值搜索
在每个fold的训练集上:
  thr* = argmaxt ∈ [0.05, 0.95, step=0.01] F1(y_train, prob_train >= t)

将找到的最优阈值应用于该fold的验证集预测:
  y_pred_val = (prob_val >= thr*)

SHAP排名计算

SHAP (SHapley Additive exPlanations) 特征排名
1. 训练XGBoost: model = XGBoost(X_all_features, y)
2. 创建TreeExplainer: explainer = shap.TreeExplainer(model)
3. 计算SHAP值: shap_values = explainer.shap_values(X_all)
4. 计算平均绝对SHAP: mean_abs = mean(|shap_values|, axis=0)
5. 按mean_abs降序排列
6. 新特征的排名 = 其在排序中的位置 (1-based, 1=最重要)

排名越低（数值越小）= 该特征越重要

L3通过条件

接受条件（满足任一即可）：
  1. delta_recall > 0 且 delta_precision ≥ -0.01
  2. delta_f1 > 0
  3. delta_precision > 0 且 delta_recall ≥ -0.01

设计理念：在反洗钱场景中，Recall（召回率）最重要——漏检的代价远高于误报。因此允许Precision小幅下降（-0.01以内）来换取Recall提升。

特征合并逻辑

特征代码输出的DataFrame可能包含 wallet_id 或 tx_id 作为合并键，系统根据不同情况执行不同的合并策略。

方式一：按 tx_id 直接合并

当特征DataFrame包含 tx_id 列时，直接左连接到交易表。

# 直接左连接 result = tx_df.merge(feature_df, on="tx_id", how="left")

适用场景：特征是交易级别的，如单笔交易的金额异常分数、交易时间特征等。

方式二：按 wallet_id 双向合并

当特征DataFrame包含 wallet_id 列时，需要将钱包级特征分别合并到交易的付款方（src）和收款方（dst）。

# 步骤1：合并为付款方特征 (src) src_rename = {"wallet_id": "src", "feat_col": "feat_col_src"} result = tx_df.merge(feature_df.rename(columns=src_rename), on="src", how="left") # 步骤2：合并为收款方特征 (dst) dst_rename = {"wallet_id": "dst", "feat_col": "feat_col_dst"} result = result.merge(feature_df.rename(columns=dst_rename), on="dst", how="left")

结果：每个钱包级特征会产生两列 —— _src 后缀（付款方视角）和 _dst 后缀（收款方视角）。

示例：如果特征 "dormant_days" 是钱包级特征，合并后将产生 "dormant_days_src"（付款方的休眠天数）和 "dormant_days_dst"（收款方的休眠天数）两列。这使得模型可以分别学习付款方和收款方的风险特征。

评估方法论

5-Fold StratifiedKFold交叉验证 核心评估方式

所有模型评估均使用5折分层交叉验证，确保每折中正负样本比例与总体一致。

StratifiedKFold CV 流程
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

对每个fold (train_idx, val_idx):
  1. 训练: model.fit(X[train_idx], y[train_idx])
  2. 训练集概率: prob_train = model.predict_proba(X[train_idx])[:, 1]
  3. 找最优阈值: thr = find_best_threshold(y[train_idx], prob_train)
  4. 验证集概率: prob_val = model.predict_proba(X[val_idx])[:, 1]
  5. 应用阈值: y_pred = (prob_val >= thr)
  6. 计算指标: F1, Recall, Precision, PR-AUC

最终指标 = 5折均值
关键设计：阈值在训练集上优化，在验证集上评估。这避免了在验证集上"偷看"造成的过拟合评估偏差。
评估指标详解 4个核心指标
F1 Score
F1 = 2 × (Precision × Recall) / (Precision + Recall)

精确率和召回率的调和平均。在极度不平衡数据中，是比Accuracy更有意义的综合指标。
Recall (召回率)
Recall = TP / (TP + FN)

在反洗钱场景中最关键：漏检一笔洗钱交易的代价远高于误报。目标是尽可能发现所有洗钱行为。
Precision (精确率)
Precision = TP / (TP + FP)

标记为洗钱的交易中真正是洗钱的比例。过低会导致调查资源浪费。
PR-AUC
PR-AUC = Area Under Precision-Recall Curve

不依赖特定阈值的整体性能指标。在正样本率极低（~0.32%）时比ROC-AUC更有区分力。
基线对比评估 Baseline vs Combined

评估流程

  • 基线模型
    使用现有基线特征训练XGBoost，5-fold CV计算F1/Recall/Precision/PR-AUC作为基线性能。
  • 特征选择
    前向特征选择：逐个添加使F1最高的候选特征，直到无法再提升。同时确保Recall不下降超过0.01。
  • 组合模型
    使用基线特征+选中的新特征训练XGBoost，5-fold CV计算组合模型性能。
  • 增量计算
    delta = combined_metrics - baseline_metrics，正值表示新特征带来了性能提升。

前向特征选择算法

def forward_select_features(X_baseline, candidates, y, baseline_metrics): remaining = set(candidates.keys()) selected = [] current_f1 = baseline_metrics["f1"] while remaining: best_name, best_f1 = None, current_f1 for name in remaining: X_try = X_current + candidate[name] m = compute_cv_metrics(X_try, y) # 5-fold CV if m["f1"] > best_f1: best_f1 = m["f1"] best_name = name if best_name is None: break # 无特征能提升F1，停止 # 检查Recall不能下降太多 if best_metrics["recall"] < baseline_metrics["recall"] - 0.01: remaining.discard(best_name) continue selected.append(best_name) return selected
综合打分机制 加权评分
特征综合评分公式
Score = w_shap × norm(1/shap_rank) + w_iv × norm(iv) + w_red × norm(1-redundancy) + w_delta × norm(delta_f1)

权重配置:
  w_shap = 0.30 (SHAP重要性排名)
  w_iv = 0.20 (信息值)
  w_red = 0.20 (低冗余度奖励)
  w_delta = 0.30 (模型增量F1)

norm(): Min-Max归一化到[0,1]区间

架构选择建议

选择单Agent系统当...
  • 需要快速原型验证特征方向
  • LLM API调用预算有限
  • 探索性研究，不确定哪些维度有潜力
  • 需要Agent完全自主决策的灵活性
选择多Agent系统当...
  • 对特征鲁棒性有严格要求
  • 需要对抗性思维确保特征不易被规避
  • 需要完整的审计日志和决策追溯
  • 面向生产部署，需要监管合规
