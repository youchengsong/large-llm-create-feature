1核心思想：Agent 即特征工程师

本系统的核心不是一条固定流水线，而是一个 LLM Agent（大语言模型智能体）在自主执行特征工程任务。Agent 阅读领域知识、探索数据分布、生成特征代码、提交验证、根据反馈调整策略——就像一个人类特征工程师的工作流程，但由 LLM 自主驱动。

Agent 与传统流水线的区别 传统特征工程流水线是预定义的：固定的特征模板 → 批量计算 → 筛选。而本系统中，LLM Agent 是自主决策的：它决定生成什么特征、如何实现、失败后如何调整。外围模块（沙盒、验证器、SHAP 分析器）是 Agent 的工具和环境，而不是控制它的流水线。

1.1 Agent 视角下的系统角色划分

AGENT LLM 特征工程师
  • 阅读数据 Schema、分布差异、领域知识
  • 自主决定探索哪个维度、生成什么特征
  • 编写 Python 特征代码
  • 根据验证反馈调整策略（换方向、改实现）
  • 在失败后自动修复代码（最多 2 次）
ENVIRONMENT 外围工具与反馈
  • 沙盒：安全执行 Agent 提交的代码
  • 三级验证器：L1(安全) → L2(统计) → L3(模型增量)
  • SHAP 分析器：告诉 Agent 哪些维度薄弱
  • 候选缓冲池：暂存 L3 未通过但有潜力的特征
  • 前向选择器：在轮末评估特征组合效应

1.2 核心设计理念

Recall 优先

反洗钱场景中漏检代价远高于误报。所有验证条件以 Recall 提升为必要条件，Precision 只设绝对下限（95%）。

动态基线

Agent 每接受一个特征，existing_features 立即更新。后续所有评估都基于最新特征集，确保增量的真实性。

3Agent 的知识注入

Agent 的能力来源于两部分：LLM 自身的通用知识 + 通过 System Prompt 注入的领域特定知识。System Prompt 是 Agent "读到的第一份资料"，相当于给它一份详尽的工作手册。

4Agent 的工具箱

Agent 通过 OpenAI Function Calling 协议调用工具。每个工具定义了名称、参数 Schema 和描述，Agent 自主决定何时调用哪个工具。

TOOL explore_data

作用：在 DataFrame 上执行查询代码，探索数据分布。

参数：question（问题描述） + code（Python 代码）

超时：15 秒

Agent 在生成特征前可以先探索数据，验证自己的假设。

TOOL generate_feature

作用：提交特征的代码、名称、维度、解释、推理过程。

参数：feature_name / dimension / code / explanation / reasoning

代码签名固定：def feature_xxx(open_df, tx_df, close_df) → pd.DataFrame

TOOL execute_sandbox

作用：触发完整的 L1 → L2 → L3 验证流水线。

参数：feature_name（自动关联之前 generate_feature 的代码）

这是 Agent 获得验证反馈的唯一入口。返回的结果包含所有指标和判定。

Agent 的自主权 工具只是 Agent 的能力边界，不是执行脚本。Agent 自主决定：是否先 explore_data 了解数据，一次生成几个特征，失败后是换方向还是改实现。环境（外围系统）只在 Agent 调用 execute_sandbox 时才介入评估。

5环境：三级验证流水线

当 Agent 调用 execute_sandbox 时，环境自动执行三级验证。Agent 无需关心验证细节，只需读取返回的结果并据此调整策略。

5.1 L1：沙盒执行验证 ENV

检查项内容
安全检查AST 解析，禁止 os、sys、subprocess、open、eval 等
执行方式独立进程 + 90 秒超时
输出校验含 wallet_id 或 tx_id；非空；NaN < 50%；nunique > 1
自动修复失败时，环境自动调用 Agent（以代码修复身份）修复代码，最多 2 次
L1 的自动修复机制 当代码执行失败，环境会将错误信息发给 Agent（此时用低温度 0.3 的修复模式），Agent 输出修复后的代码，环境再次执行。这形成一个小型的 Agent-环境子循环，让 Agent 有机会修正语法错误或逻辑问题。

5.2 L2：统计质量验证 ENV

指标含义阈值
IV正负样本分布差异（分箱后计算）≥ 校准值（噪声基准调整）
KS正负样本累积分布最大分离度≥ 校准值
冗余度与已有特征的最大 |Pearson 相关系数|< 0.7
缺失率NaN 比例≤ 0.5

5.3 L3：模型增量验证 ENV

在当前 existing_features（动态基线）上评估新特征的增量贡献。5-fold StratifiedKFold CV，每折搜索最优 F1 阈值。

L3 接受条件（Recall 优先）：
  1. delta_recall > 0 — Recall 必须有提升
  2. aug_precision ≥ 0.95 — 加入后 Precision 绝对值不低于 95%
通过 L3 → 立即接受

特征加入 existing_features，Agent 的后续探索在更高的基线上进行。环境还会为该特征调用 Agent 生成一份可解释性报告。

L3 未通过 → 候选缓冲池

进入候选缓冲池（Candidate Buffer），等待轮末前向选择评估组合效应。该特征可能单独无效但与其他特征互补[2]。

5.4 候选缓冲池

通过 L2 但未通过 L3 的特征进入候选缓冲池。这是一种延迟评估机制——单特征增量不够，但多特征组合可能有效。

参数值说明
最大容量20超出时淘汰互信息最低的特征
最大存活轮数3 轮超过 3 轮未被接受则清除
最大连续拒绝2 次连续 2 次被前向选择拒绝则清除

5.5 前向选择（Forward Selection）[3]

每轮所有维度探索结束后，环境对候选缓冲池中的特征执行贪心前向选择[4]——从当前 existing_features 出发，逐个尝试加入池中特征，选最优的加入，重复直到无增量。

# 前向选择（每轮末由环境自动执行，Agent 不参与）
X_current = existing_features
current_metrics = compute_cv_metrics(X_current, y)   # 动态基线

while 还有候选:
    for candidate in remaining:
        m = compute_cv_metrics(X_current + candidate, y)
        if m.recall > current_metrics.recall and m.precision >= 0.95:
            score = delta_recall + 0.3 * delta_f1     # 排序依据
    if best is None: break
    X_current += best; current_metrics = updated
L3 验证前向选择 (FS)
触发Agent 每提交一个特征时每轮结束时，环境自动执行
方式单特征增量评估贪心组合搜索
解决的问题这个特征单独有没有用？这些单独不够好的特征，组合起来有没有用？

[2] Kohavi, R. & John, G. H. "Wrappers for Feature Subset Selection." Artificial Intelligence, 97(1-2), 273-324, 1997.
[3] Guyon, I. & Elisseeff, A. "An Introduction to Variable and Feature Selection." JMLR, 3, 1157-1182, 2003.

6Agent 的搜索策略

Agent 不是随机探索。环境通过分组任务指派和SHAP 反馈引导 Agent 的搜索方向。

6.1 分组搜索

特征空间按业务含义划分为 4 个维度组[5]，环境在每轮中依次向 Agent 指派维度任务，每组有独立的候选预算，保证多维度均衡探索。

维度组关联字段探索方向
金额频次 amount, interval, hour, transaction_motif 金额分布异常、交易频率模式、金额集中度等
时间地域 timestamp, src_ip, dst_ip, region_code, hour 夜间交易、IP 多样性、地域异常、时间集中度等
行为序列 timestamp, transaction_mode, zs_timestamp 交易模式转移、序列自相关、收支不平衡等
主体关联 wallet_open_cert, wallet_open_tel, src_device 设备共享、身份复用、fan-in/fan-out 模式等

[5] 分组搜索的思路借鉴了进化计算中的分治策略：将搜索空间分割为独立子群，各自探索后交换优秀个体。参见 Whitley, D. et al. "The Island Model Genetic Algorithm: On Separability, Population Size and Convergence." J. Computing and Information Technology, 1999.

6.2 SHAP 驱动的预算分配 ENV

每轮开始时，环境计算当前模型各维度的 SHAP 重要性，按反比分配预算：薄弱维度获得更多探索资源（借鉴 MedFeat[6]）。

weight[dim] = 1.0 / (importance[dim] + eps)
budget[dim] = round(weight[dim] / sum(weights) * B_total)   # B_total = 12
budget[dim] = clamp(budget[dim], min=1, max=5)

这些预算通过任务指令注入 Agent 的 prompt："请为金额频次维度生成 4 个候选特征"。

[6] "MedFeat: Model-Aware and Explainability-Driven Feature Engineering with LLMs." arXiv:2603.02221, 2026.

6.3 组内多轮对话

每个维度组在每轮中最多进行 2 轮有效对话：

轮次Agent 收到的信息退出条件
Turn 1 维度任务 + SHAP 反馈 + 高分示例 + 失败记忆 有特征被 L3 接受 → 退出（已有收获）
无失败特征 → 退出（无产出）
Turn 2 Turn 1 的通过/失败反馈 → Agent 调整方向重试 无论结果如何，强制退出进入下一维度组

7Agent 的记忆与学习

Agent 在多轮探索中积累经验，这些"记忆"通过对话历史和结构化数据实现。

7.1 对话上下文（短期记忆）

Agent 与环境的所有交互都保存在 messages 列表中。这意味着 Agent 在后续轮次中能"记住"：

  • 之前生成过哪些特征（避免重复）
  • 哪些方向失败了、为什么失败（调整策略）
  • 哪些特征被接受了、指标如何（学习成功模式）

7.2 失败记忆（FailureMemory） ENV

环境维护一个结构化的失败记录库，每个失败特征记录名称、代码、失败原因。每轮注入 prompt 时取最近的失败案例，显式告诉 Agent "避免重复这些错误"。

7.3 跨维度知识传播 ENV

当一个维度组产出高分特征，环境自动将该特征的信息传播到其他维度组（migrate_best）。下次 Agent 在其他维度探索时，能看到跨维度的高分示例作为参考。

7.4 可解释性报告 AGENT

每个通过 L3 的特征，环境调用 Agent（以分析专家身份）生成可解释性报告，包含：

value_meaning

特征值的业务含义

risk_threshold

风险阈值建议

synergy

与其他特征的协同效应

false_positive_cases

可能的误报场景

regulatory_explanation

面向监管的一句话解释

8收敛检测与终止

Agent 的搜索不是无限的。环境通过以下条件控制终止：

  • 收敛终止：连续 2 轮没有新特征被接受（L3 直通 + 前向选择 均无产出）→ Agent 已穷尽有效搜索空间
  • 目标达成：已接受特征数达到上限（默认 30）
  • 轮次上限：完成 10 轮迭代

终止后环境执行最终的候选缓冲池评估，给剩余候选最后一次机会。

11与传统方法的对比

传统特征工程本系统（LLM Agent）
特征来源 人工设计或模板库 Agent 根据领域知识和数据分布自主设计
搜索策略 穷举预定义模板 Agent 根据 SHAP 反馈动态调整搜索方向
失败处理 跳过或人工调整 Agent 自动修复代码 + 根据失败记忆避免重复
组合效应 通常忽略 候选缓冲池 + 前向选择捕获互补效应
可解释性 事后补充 Agent 对每个接受特征生成结构化解释
扩展性 新领域需重新设计模板 更换 System Prompt 中的领域知识即可适配

12.5 结果分析

关键发现
  1. Agent 具备领域推理能力：3 个特征均源自 Agent 对领域知识的深度理解——从判决书中的"限额控制"推导出金额集中度，从 region 风险差异推导出地域×夜间交叉特征，从交易模式分布异常推导出 fan_in + 无 single 组合。
  2. Recall 优先策略有效：3 个特征累计提升 Recall +0.67%（绝对值），在正样本率仅 0.32% 的极度不平衡数据上，这意味着多召回约 30 笔洗钱交易。
  3. Precision 代价可控：Precision 仅下降 0.19%（从 99.00% 到 98.82%），仍保持在极高水平。
  4. 动态基线严格过滤：候选缓冲池的 4 次前向选择均未选出特征（累计评估约 80 个组合），说明动态基线有效防止了"虚假增量"。
  5. 多维度覆盖：3 个特征分别来自金额频次、时间地域、行为序列三个维度组，分组搜索策略保证了广度。
  6. 高淘汰率体现质量控制：43 个候选中仅 3 个通过（7.0%），三级验证环境起到了严格的质量把关作用。
