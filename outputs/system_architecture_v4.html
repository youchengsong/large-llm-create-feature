1核心思想

本系统的核心是一个 LLM Agent（大语言模型智能体）在自主执行特征工程任务。Agent 阅读领域知识、探索数据分布、生成特征代码、提交验证、根据反馈调整策略，并能根据数据类型选择合适的下游模型进行训练与评估，由 LLM 自主驱动。

Agent 与传统方法的区别 传统特征工程是预定义的：固定的特征模板 → 批量计算 → 筛选，模型选择也是人工指定的。而本系统中，LLM Agent 是自主决策的：它决定生成什么特征、如何实现、失败后如何调整，还能根据数据特性选择最优的下游模型。外围模块（沙盒、验证器、SHAP 分析器）是 Agent 的工具和环境，而不是控制它的固定流程。

1.1 Agent 视角下的系统角色划分

AGENT LLM Agent
  • 阅读数据 Schema、分布差异、领域知识
  • 自主决定探索哪个维度、生成什么特征
  • 编写 Python 特征代码
  • 根据验证反馈调整策略（换方向、改实现）
  • 在失败后自动修复代码（最多 2 次）
  • 根据数据类型和任务特性，自主选择下游训练模型（XGBoost / LightGBM / RandomForest 等）
ENVIRONMENT 外围工具与反馈
  • 沙盒：在隔离环境中执行 Agent 提交的代码（E2B microVM 或本地进程）
  • 三级验证器：L1(安全) → L2(统计) → L3(模型增量)
  • SHAP 分析器：告诉 Agent 哪些特征重要
  • 候选缓冲池：暂存 L3 未通过但有潜力的特征
  • 前向选择器：在轮末评估特征组合效应
  • 模型训练接口：支持多种下游模型的训练与推理

1.2 核心设计理念

Recall 优先

反洗钱场景中漏检代价远高于误报。所有验证条件以 Recall 提升为必要条件，Precision 只设绝对下限（95%）。

动态基线

Agent 每接受一个特征，existing_features 立即更新。后续所有评估都基于最新特征集，确保增量的真实性。

模型自适应

Agent 不绑定单一模型，可根据数据类型（表格型、时序型、图结构等）自主选择最合适的下游模型进行特征评估和最终训练。

端到端闭环

系统覆盖从领域知识注入、特征生成、统计验证到模型训练推理的完整链路，Agent 不仅是特征工程师，更是整个数据科学流程的驱动者。

3Agent 的知识注入

Agent 的能力来源于两部分：LLM 自身的通用知识 + 通过 System Prompt 注入的领域特定知识。System Prompt 是 Agent "读到的第一份资料"，相当于给它一份详尽的工作手册。总注入量约 8000~12000 tokens，涵盖数据结构、领域知识、行为约束三大板块。

3.4 专家意见 + 裁判文书知识

这部分知识来自两个独立来源，在 System Prompt 中分两段注入：

来源 A：邮储银行专家意见

来源文件：邮储专家意见_数币洗钱模式.docx

由邮储银行反洗钱专家总结的 4 种数字人民币洗钱运营模式：

  1. 薅羊毛：批量注册4类钱包，同一身份证/手机号关联多个钱包，利用红包/优惠活动
  2. 线下跑分：个人钱包收到大额转入后立即转出，交易对手固定，金额接近限额
  3. 线上跑分：凌晨高频交易(20时-1时)，分散转出(fan_out)模式，金额10-1000元
  4. 商户收款码跑分：商户钱包大量收款后转至个人钱包，many_to_many模式，佣金约0.5-1%

  • 特征表现：转出金额 ≈ 转入金额 × (1 - 佣金率)，差额为固定比例

5.2 L2：统计质量验证 ENV

指标全称含义阈值
IV Information Value
（信息价值）		 衡量特征对正负样本的区分能力。将特征分箱后，计算每个箱中正负样本分布的差异总和。IV < 0.02 通常认为无预测力，0.02~0.1 弱预测力，0.1~0.3 中等，> 0.3 强预测力。 ≥ 校准值
（基于随机噪声特征的 IV 动态确定基线，排除偶然波动）
KS Kolmogorov-Smirnov
（K-S 统计量）		 衡量正负样本累积分布函数（CDF）之间的最大距离。KS 值越大，说明该特征越能将正负样本在某个切分点上分开。常用于信用评分模型中评估变量区分力。 ≥ 校准值
（同样基于噪声基准动态校准）
冗余度 Max |Pearson r|
（最大皮尔逊相关系数绝对值）		 新特征与已有特征集中每个特征的 Pearson 相关系数绝对值的最大值。过高说明新特征与已有特征高度线性相关，不提供新信息。 < 0.7
缺失率 Missing Rate
（NaN 比例）		 特征中缺失值占总样本的比例。过高的缺失率会导致模型训练不稳定，且可能暗示特征计算逻辑有问题。 ≤ 0.5

校准值的计算方法（噪声基线法）

固定阈值（如 IV ≥ 0.02）在不同数据集上表现不稳定——正样本率仅 0.32% 的极度不平衡数据中，纯随机噪声也可能因采样偶然性产生较高的 IV/KS。系统采用噪声基线法动态校准阈值：

校准算法（实验开始时执行一次）
  1. 生成噪声特征：用固定随机种子（seed=42）生成 100 个标准正态分布随机特征（与真实数据等长，但与标签完全无关）
  2. 计算噪声指标：对每个噪声特征计算 IV 和 KS，得到 100 个 IV 值和 100 个 KS 值的分布
  3. 取 95 分位数：calibrated_iv = max(percentile(noise_ivs, 95), 0.001)，KS 同理
  4. 设为阈值：候选特征的 IV/KS 必须超过此校准值才算通过 L2
# 噪声基线校准（伪代码）
rng = np.random.RandomState(42)
noise_ivs, noise_ks = [], []

for i in range(100):                           # 生成 100 个随机噪声特征
    noise = pd.Series(rng.randn(n_samples))    # 标准正态分布，与标签无关
    noise_ivs.append(compute_iv(noise, label))
    noise_ks.append(compute_ks(noise, label))

iv_threshold = max(np.percentile(noise_ivs, 95), 0.001)   # 取 p95
ks_threshold = max(np.percentile(noise_ks, 95), 0.001)    # 取 p95
为什么是 95 分位数？

对应统计学中 p < 0.05 的显著性水平。即：如果一个特征的 IV/KS 落在随机噪声分布的 95% 以上，那么它"纯属偶然"的概率不超过 5%，我们有 95% 的信心认为它具有真实区分力。

为什么不用固定值？

经典的 IV ≥ 0.02 阈值假设数据均衡。但在 0.32% 正样本率下，噪声特征的 IV 可能本身就波动在 0.01~0.03 之间。固定阈值会放过大量"看似有效但实际是噪声"的特征，校准法自适应地解决了这个问题。

5.3 L3：模型增量验证 ENV

在当前 existing_features（动态基线）上评估新特征的增量贡献。5-fold StratifiedKFold CV，每折搜索最优 F1 阈值。

L3 接受条件（Recall 优先）：
  1. delta_recall > 0 — Recall 必须有提升
  2. aug_precision ≥ 0.95 — 加入后 Precision 绝对值不低于 95%
通过 L3 → 立即接受

特征加入 existing_features，Agent 的后续探索在更高的基线上进行。环境还会为该特征调用 Agent 生成一份可解释性报告。

L3 未通过 → 候选缓冲池

进入候选缓冲池（Candidate Buffer），等待轮末前向选择评估组合效应。该特征可能单独无效但与其他特征互补[2]。

5.4 候选缓冲池

通过 L2 但未通过 L3 的特征进入候选缓冲池。这是一种延迟评估机制——单特征增量不够，但多特征组合可能有效。

参数值说明
最大容量20超出时淘汰互信息最低的特征

5.5 前向选择（Forward Selection）[3]

每轮所有维度探索结束后，环境对候选缓冲池中的特征执行贪心前向选择[4]——从当前 existing_features 出发，逐个尝试加入池中特征，选最优的加入，重复直到无增量。

7Agent 的记忆与学习

Agent 在多轮探索中积累经验，这些"记忆"通过对话历史和结构化数据实现。

7.1 对话上下文（短期记忆）

Agent 与环境的所有交互都保存在 messages 列表中。这意味着 Agent 在后续轮次中能"记住"：

  • 之前生成过哪些特征（避免重复）
  • 哪些方向失败了、为什么失败（调整策略）
  • 哪些特征被接受了、指标如何（学习成功模式）

7.2 失败记忆（FailureMemory） ENV

环境维护一个结构化的失败记录库，每个失败特征记录名称、代码、失败原因。每轮注入 prompt 时取最近的失败案例，显式告诉 Agent "避免重复这些错误"。

7.3 跨维度知识传播 ENV

当一个维度组产出高分特征，环境自动将该特征的信息（名称、代码、指标、SHAP 排名）传播到其他维度组（migrate_best）。下次 Agent 在其他维度探索时，能看到跨维度的高分示例作为参考，可能激发交叉维度的特征灵感。

知识传播示例 Agent 在「金额频次」维度生成了高分特征 amount_concentration_pattern（金额集中度），该特征的信息随后注入到「时间地域」维度的 prompt 中。Agent 在探索「时间地域」时看到这个跨维度示例，可能设计出"金额集中度 × 夜间交易"的交叉特征。

8收敛检测与终止

Agent 的搜索不是无限的。环境通过以下条件控制终止：

终止条件判定标准设计意图
收敛终止 连续 2 轮没有新特征被接受（L3 直通 + 前向选择均无产出） Agent 已穷尽有效搜索空间。在当前知识和数据条件下，继续探索的边际收益趋近于零。
目标达成 已接受特征数达到上限（默认 30） 防止特征过多导致维度灾难。30 个新特征 + 95 个基线已足够覆盖各维度。
轮次上限 完成 10 轮迭代 硬性时间/成本上限。每轮约 1 小时（含 4 维度探索 + 前向选择），10 轮 ≈ 10 小时。

终止后环境执行最终的候选缓冲池评估，给剩余候选最后一次前向选择机会。然后输出完整的实验报告：接受的特征列表、指标汇总、搜索日志。

实际收敛情况 在首次实验中，Agent 在第 4 轮即触发收敛终止：第 1-2 轮接受了 3 个特征，第 3-4 轮连续无新产出。这表明在当前基线（95 个人工特征）较强的情况下，Agent 能找到的增量空间确实有限——3 个特征已经是有效的补充。

9.2 交叉验证策略

使用 5-fold StratifiedKFold 交叉验证。Stratified 保证每折的正负样本比例与整体一致（0.32% 正样本率），避免某些折完全没有正样本。最终指标为 5 折平均值。

9.3 阈值优化

不使用固定 0.5 阈值（在极度不平衡数据上 0.5 阈值几乎预测全负）。每折训练集上遍历 0.05~0.95（步长 0.01），选使 F1 最大的阈值，在验证集上计算最终指标。这确保阈值选择不受验证集信息泄露影响。

维度组数 4 金额频次 / 时间地域 / 行为序列 / 主体关联。按业务语义划分，保证搜索广度覆盖交易数据的各个方面。
B_total 12 每轮总候选预算（所有维度组共享）。由 SHAP 反馈按反比分配到各组。例如薄弱维度可能分得 5 个名额，强势维度只有 1 个。
组内对话轮数 2 每个维度组最多 2 轮有效对话。Turn 1 给 Agent 任务指令 + 上下文；如果有失败特征，Turn 2 给 Agent 反馈让其调整方向。防止在单个维度上过度消耗 token。
L2 阈值 iv_min 校准值 Information Value 最小阈值。基于噪声特征的 IV 分布动态确定（取 95 分位数），排除随机波动。典型值约 0.01~0.02。
ks_min 校准值 KS 统计量最小阈值。同样基于噪声基准校准。KS 衡量正负样本 CDF 最大分离度，过低说明特征无区分力。
corr_max 0.7 最大冗余度。新特征与已有特征的 |Pearson r| 不得超过 0.7。高相关意味着信息重复，加入后反而增加过拟合风险。
missing_rate_max 0.5 最大缺失率。超过 50% NaN 的特征说明覆盖度不足，可能是计算逻辑有缺陷（如 JOIN 失败或条件过严）。
L3 / FS delta_recall > 0 Recall 必须有正向提升（哪怕很小）。反洗钱场景中漏检代价极高，任何能多召回一笔可疑交易的特征都有价值。
aug_precision ≥ 0.95 加入特征后的 Precision 绝对值不低于 95%。这是 Precision 的下限保护——允许 Recall 提升带来的小幅 Precision 下降，但不能降太多。
候选缓冲池 max_size 20 缓冲池最大容量。超出时淘汰互信息（MI）最低的特征。避免无限积累导致前向选择搜索空间过大。
max_age 3 最大存活轮数。超过 3 轮仍未被前向选择接受的特征，说明在多种特征组合下都无增量，清除释放空间。
max_rejects 2 最大连续被前向选择拒绝次数。连续 2 次不被选中说明该特征大概率无法与任何组合产生互补效应。
收敛 连续空轮 2 连续 2 轮没有任何新特征被接受（L3 直通 + 前向选择均无产出），判定 Agent 已穷尽有效搜索空间，终止实验。
沙盒 执行超时 90s 代码执行时间限制。超时后强制终止进程/沙盒。大多数特征计算在 10s 内完成，90s 给复杂聚合留足余量。
隔离后端 E2B / local E2B：Firecracker microVM（硬件虚拟化，独立内核），推荐用于生产环境；local：进程隔离 + AST 白名单 + builtins 替换，适合本地调试。通过 SANDBOX_MODE 环境变量切换。
L1 修复 自动修复次数 2 代码执行失败时，环境将错误信息发给 Agent（低温度 0.3 修复模式），Agent 输出修复代码后再次执行。最多重试 2 次，避免无限修复循环。

12.5 结果分析

关键发现
  1. Agent 具备领域推理能力：3 个特征均源自 Agent 对领域知识的深度理解——从裁判文书中的"限额控制"推导出金额集中度，从 region 风险差异推导出地域×夜间交叉特征，从交易模式分布异常推导出 fan_in + 无 single 组合。
  2. Recall 优先策略有效：3 个特征累计提升 Recall +0.67%（绝对值），在正样本率仅 0.32% 的极度不平衡数据上，这意味着多召回约 30 笔洗钱交易。
  3. Precision 代价可控：Precision 仅下降 0.19%（从 99.00% 到 98.82%），仍保持在极高水平。
  4. 动态基线严格过滤：候选缓冲池的 4 次前向选择均未选出特征（累计评估约 80 个组合），说明动态基线有效防止了"虚假增量"。
  5. 多维度覆盖：3 个特征分别来自金额频次、时间地域、行为序列三个维度组，分组搜索策略保证了广度。
  6. 高淘汰率体现质量控制：43 个候选中仅 3 个通过（7.0%），三级验证环境起到了严格的质量把关作用。

14修改方案

方向概述：以下四项修改方案将从场景粒度、输出质量、系统安全、模型能力四个维度对系统进行全面升级。

14.1 场景细分 — 按犯罪类型注入专属领域知识

现状：当前系统将所有异常交易统一为"洗钱"一个类别，领域知识按统一模式注入。

改进：根据不同犯罪场景（诈骗、赌博、洗钱等）进行细粒度分类，为每种场景注入特有的领域知识。

  • 不同犯罪类型的资金流转模式差异显著（如赌博偏好高频小额、诈骗偏好单向大额转出）
  • 为每种场景构建独立的风险指标子集和检测规则
  • Agent 在生成特征时可根据目标场景选择对应的知识模块
  • 参考BABD-13 数据集的场景细分实践，验证方案可行性

14.2 输出结果可解释性增强

现状：系统输出以特征代码和指标数值为主，缺少面向业务人员的可解释性说明。

改进：强调输出结果的可解释性，为每个生成的特征配套可解释性文件。

  • 每个特征附带：领域含义说明、对应的领域知识来源（哪条规则/哪个模式）、SHAP 贡献分析
  • 生成可视化报告：特征重要性排序、特征与标签的分布对比、领域知识覆盖率
  • 输出格式标准化，便于监管审查和业务理解
  • 支持追溯：从最终特征反向追踪到原始领域知识条目

14.3 代码安全检测与特征评估方案优化

现状：L1 沙盒基于 RestrictedPython + exec()，L2 使用 IV/KS + 噪声校准。

改进：继续调研更优的代码安全方案和特征评估指标。

  • 代码安全方向：
    • 调研容器级沙盒（如 gVisor、Firecracker）是否比 RestrictedPython 更安全
    • 调研 AST 静态分析 + 动态沙盒的组合方案
    • 评估当前白名单机制的覆盖率和漏洞风险
  • 特征评估方向：
    • 调研 PSI（Population Stability Index）作为特征稳定性的补充指标
    • 探索互信息（Mutual Information）替代或补充 IV 的可行性
    • 评估是否引入时序验证（Time-based Split）替代随机交叉验证

14.4 接入 Agent 模型训练模块

现状：Agent 生成特征后，系统仅通过 XGBoost 交叉验证评估特征质量，缺少独立的模型训练和推理流程。

改进：接入下游模型训练接口，使系统具备完整的「特征生成 → 模型训练 → 推理预测」闭环能力。

  • Agent 生成并筛选出有效特征后，自动触发下游模型训练流程
  • 支持将基线特征 + Agent 生成特征组合为最终特征集，训练生产级模型
  • 提供模型推理接口，对新数据进行实时/批量预测
  • 支持模型版本管理：不同特征组合对应不同模型版本，便于对比和回滚
