特征验证方案 v2 — Recall 优先策略

2026-05-19 | 单Agent特征工程系统 | 数字人民币反洗钱

1. 背景与问题

在反洗钱检测场景中，Recall（召回率）是最关键的指标——漏掉一笔可疑交易的代价远大于多报一笔误报。系统需要尽可能"不放过"异常交易。

v1 方案的问题

原有验证方案以 F1 为中心，L3 验证的接受条件过于宽松：

  • 条件2（delta_f1 > 0）允许 Recall 下降只要 Precision 补偿足够
  • 条件3（delta_precision > 0 且 delta_recall >= -0.01）直接允许 Recall 下降
  • 结果：Agent 接受了 30 个特征，但其中 28 个实际损害了 Recall
  • Forward Selection 从 30 个中只能选出 2 个真正有用的，效率极低

3. L3 模型验证 — 条件对比

L3 是 Agent 运行过程中的实时门槛。每生成一个特征，立即评估是否接受。通过 L3 的特征会加入 existing_features 池，影响后续特征的评估基准。

v1 旧方案

F1 中心，三条件取或

# 满足任一即接受 (delta_recall > 0 and delta_precision >= -0.01) or (delta_f1 > 0) or (delta_precision > 0 and delta_recall >= -0.01)

问题：条件2和3允许 Recall 下降，污染特征池

v2 新方案

Recall 优先，三条件取且

# 必须同时满足 delta_recall > 0 # Recall 必须提升 and delta_f1 >= -0.001 # F1 允许微降 and delta_precision >= -0.001 # Precision 允许微降

Recall 提升是硬门槛，其他指标有容忍度

4. Forward Selection — 条件对比

Forward Selection 是 Agent 运行结束后的最终筛选。从基线开始，逐个尝试加入候选特征，只保留真正有增量的。

v1 旧方案

F1 主导排序

# 硬门槛 delta_f1 >= 0 # 排序分数 score = delta_f1 + delta_recall

F1 不能降，排序也以 F1 为主

v2 新方案

Recall 主导排序

# 接受条件（与 L3 一致） delta_recall > 0 and delta_f1 >= -0.001 and delta_precision >= -0.001 # 排序分数 score = delta_recall + 0.3 * delta_f1

Recall 提升优先，F1 作为辅助打破平局

5. L3 与 Forward Selection 的关系

维度 L3 模型验证 Forward Selection
执行时机 Agent 运行过程中，实时评估 Agent 运行结束后，最终筛选
评估基准 当前 existing_features 池（动态变化） 固定的原始基线特征（95个）
作用 决定特征是否进入候选池 从候选池中选出最终使用的子集
接受条件 v2 方案统一：delta_recall > 0, delta_f1 >= -0.001, delta_precision >= -0.001
排序逻辑 不涉及排序 delta_recall + 0.3 * delta_f1

L3 和 FS 条件统一后，不会再出现"L3 接受 30 个，FS 只留 2 个"的浪费。L3 阶段就会过滤掉不提升 Recall 的特征，让 Agent 的搜索预算集中在真正有效的方向。

7. v2 方案预期效果

  • L3 通过率下降：不再接受纯 Precision 提升的特征，预计 L3 通过的特征从 30 个降至 5-10 个，但每个都真正提升 Recall
  • existing_features 池更干净：池中不会被无用特征污染，后续特征的评估基准更准确
  • 搜索预算更集中：Agent 不会把名额浪费在无效特征上，有更多机会探索高价值方向
  • L3 与 FS 一致：不再出现大量 L3 接受但 FS 拒绝的浪费
  • Precision 可控让步：允许 Precision 微降 0.001，换取更多 Recall 提升空间
