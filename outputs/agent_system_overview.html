1. 系统目标

利用大语言模型（DeepSeek-Chat）自动生成反洗钱检测特征，在95个人工基线特征的基础上，通过自动化搜索发现新的有效特征，提升模型的Recall（召回率）——在反洗钱场景中，漏掉一笔可疑交易的代价远大于误报。

系统以单Agent方式运行，Agent通过工具调用（Tool Use）与沙箱交互，自主完成特征设计、代码生成、验证评估的全流程。

2. 数据基础

系统基于三张核心数据表：

表名描述规模关键字段
open_df 开户表 钱包注册信息 ~100,000 行 wallet_id, wallet_open_cert, wallet_open_tel, region_code, wallet_type ...
tx_df 交易表 转账交易记录 1,384,512 行 tx_id, src, dst, amount, timestamp, src_ip, dst_ip, transaction_mode, is_risk ...
close_df 销户表 钱包注销记录 ~500 行 wallet_id, zs_timestamp, zs_channel ...

标签：tx_df.is_risk（交易级），正样本 4,484 笔，正样本率 0.3239%（极度不平衡）

三表关联：交易表的 src/dst 字段是 wallet_id，关联到开户表和销户表

3. 基线特征

人工构建的 106 个特征中，去掉标签列 is_laundering 和 10 个指定弱特征后，保留 95 个基线特征作为起点。

去掉的10个特征：Min_Received, Min_Sent, wallets_per_cert_From, Max_Sent, S_src_counterparty_index, Timestamp_Hour, S_dst_counterparty_index, 1H_frequency_From, 1H_frequency_To, min_inactive_period_From

基线模型：XGBoost 5-fold Stratified CV，scale_pos_weight=19，eval_metric=aucpr，device=cuda

5. Agent 架构

基于 OpenAI Function Calling 协议，Agent 拥有 3 个工具：

工具功能使用场景
explore_data 执行 Python 代码查看数据分布 Agent 需要查看具体数据才能设计特征时
generate_feature 提交特征代码（名称+维度+代码+解释） 设计好特征后提交代码
execute_sandbox 沙箱执行 + 自动触发 L1→L2→L3 验证 提交后立即验证，返回完整评估反馈

调用流程：Agent 先 generate_feature 提交代码，然后 execute_sandbox 验证。系统自动完成 L1 代码执行 → L2 统计检验 → L3 模型评估的完整流水线，将结果反馈给 Agent。

6. 岛屿探索策略

特征空间被划分为 4 个维度岛屿，系统逐岛分配任务，确保全面覆盖：

amount_frequency

金额频次

金额分布、频率、拆分交易

字段: amount, interval, hour, transaction_motif
time_region

时间地域

夜间交易、IP跳变、跨地域

字段: timestamp, src_ip, dst_ip, region_code, hour
behavior_sequence

行为序列

休眠激活、交易对手更换、用途偏离

字段: timestamp, transaction_mode, zs_timestamp, zs_channel
entity_association

主体关联

交叉转账网络、身份复用、设备共享

字段: wallet_open_cert, wallet_open_tel, src_device, dst_device, src, dst

轮次结构

  • 外层：最多 10 轮（T=10），每轮遍历全部 4 个岛屿
  • 内层：每个岛屿每轮最多 3 轮对话（intra_island_turns=3），有反馈的多轮生成
  • 预算分配：第1轮每岛3个候选（b=3），后续轮基于 SHAP 反馈反比分配（薄弱维度分更多预算）
  • 总预算：每轮 12 个候选（B_total=12），每岛最少1个（b_min=1），最多5个（b_max=5）
  • 收敛检测：连续2轮无新特征自动终止
  • 目标上限：最多接受 30 个特征

7. 三级验证流水线

L1 代码验证

  • 沙箱执行特征代码（90秒超时）
  • 检查输出格式（DataFrame + 正确列名）
  • 失败后自动让 LLM 修复代码（最多重试2次）
  • 通过后 merge 到交易表

L2 统计验证

  • IV (Information Value) ≥ 校准阈值
  • KS (Kolmogorov-Smirnov) ≥ 校准阈值
  • 冗余度（与已有特征最大相关系数）< 0.7
  • 缺失率 ≤ 50%
  • 阈值由噪声基线校准（100个随机特征的p95分位）

L3 模型验证

  • 将新特征加入 existing_features 后做 5-fold CV
  • 计算 delta_recall, delta_f1, delta_precision
  • 计算 SHAP rank（新特征在全部特征中的重要性排名）
  • 接受条件见下方 v2 策略
  • L3 不通过 → 进入缓刑池

8. L3 验证 — Recall 优先策略 (v2)

反洗钱场景中 Recall 是最关键指标，不能漏过可疑交易。v2 策略以 Recall 为核心重新设计了接受条件。

v1 旧方案

F1 中心，三条件取或

# 满足任一即接受 (delta_recall > 0 and delta_precision >= -0.01) or (delta_f1 > 0) or (delta_precision > 0 and delta_recall >= -0.01)

问题：条件2和3允许 Recall 下降，污染特征池

v2 新方案

Recall 优先，三条件取且

# 必须同时满足 delta_recall > 0 # Recall 必须提升 and delta_f1 >= -0.001 # F1 允许微降 0.001 and delta_precision >= -0.001 # Precision 允许微降 0.001

Recall 提升是硬门槛，F1/Precision 有 0.001 容忍度

设计理由

  • delta_recall > 0：核心指标不能妥协，每个被接受的特征都必须贡献 Recall
  • delta_f1 >= -0.001：允许 F1 极小幅下降，因为 Recall 提升时 Precision 可能微降导致 F1 微降
  • delta_precision >= -0.001：Precision 也设兜底，防止为追求 Recall 导致误报率大幅上升

9. Forward Selection（前向选择）

Agent 运行结束后的最终独立评估。从基线开始，逐个尝试加入候选特征，只保留真正有增量的子集。

L3 vs Forward Selection

维度 L3 模型验证 Forward Selection
执行时机 Agent 运行过程中，每生成一个特征实时评估 Agent 运行结束后，最终筛选
评估基准 当前 existing_features 池（动态增长） 固定的原始基线特征（95个）
作用 决定特征是否进入候选池，影响后续评估基准 从候选池中选出最终使用的特征子集
接受条件 统一：delta_recall > 0, delta_f1 >= -0.001, delta_precision >= -0.001
排序逻辑 不涉及 delta_recall + 0.3 * delta_f1（Recall 主导）

Forward Selection 流程

  1. 从基线特征（95个）开始，记录当前指标
  2. 遍历所有候选特征，逐个计算加入后的 CV 指标
  3. 筛选满足接受条件的候选，按 delta_recall + 0.3 * delta_f1 排序
  4. 选最优的一个加入，更新当前特征集和指标
  5. 重复直到没有候选满足条件
v2 统一了 L3 和 FS 的接受条件后，不会再出现 "L3 接受 30 个，FS 只留 2 个" 的浪费。L3 阶段就会过滤掉不提升 Recall 的特征。

10. 辅助机制

10.1 缓刑池 (Pending Pool)

L2 通过但 L3 未通过的特征进入缓刑池，等待每轮结束时的重新评估。

  • 最大容量：20 个特征
  • 最大存活轮数：3 轮（超过自动清除）
  • 最大连续拒绝次数：2 次（超过自动清除）
  • 轮末通过 backward_eliminate_pending 重新用 Forward Selection 评估

10.2 SHAP 反馈 & 预算分配

每轮结束后计算 SHAP 特征重要性，识别薄弱维度，下一轮给薄弱维度分配更多候选预算（反比分配）。

10.3 失败记忆 (FailureMemory)

记录每个失败特征的名称、代码和失败原因，注入到后续 Prompt 中，避免 Agent 重复犯错。

10.4 可解释性报告

每个通过 L3 的特征，调用 LLM 生成可解释性报告（风险阈值、误判场景、监管解释等）。

10.5 L1 自动修复

特征代码执行失败后，自动让 LLM 分析错误并修复代码，最多重试 2 次。

10.6 Composite Score（综合打分）

每个接受的特征计算综合分数，用于岛屿内 Boltzmann 采样选择高分示例：

score = 0.30 * norm(1/SHAP_rank) + 0.20 * norm(IV) + 0.20 * norm(1 - redundancy) + 0.30 * norm(delta_f1)
