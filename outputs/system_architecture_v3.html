LLM 自动特征工程系统

基于大语言模型的反洗钱特征自动发现与验证方案

1. 系统概述

本系统利用大语言模型（DeepSeek）自动发现反洗钱检测特征。系统以岛屿探索策略遍历多个特征维度，通过三级验证流水线（L1/L2/L3）确保特征质量，使用 SHAP 反馈动态调整探索方向，并通过缓刑池 + 前向选择机制挖掘特征的组合效应。

核心设计理念

  • Recall 优先：反洗钱场景中，漏检比误报代价更高。所有验证条件以 Recall 提升为必要条件。
  • 动态基线：每接受一个新特征，后续所有验证（L3 和 FS）的基线自动更新，确保增量评估的准确性。
  • 领域知识注入：将 309 份法院判决书洗钱模式、38 个风险指标、8 种交易模式等专家知识注入 LLM prompt。

数据概况

open_df（开户表）

100,000 个钱包的开户信息：证件号、手机号、钱包等级/类型等

tx_df（交易表）

1,384,512 笔交易记录：金额、时间、IP、设备、交易模式、标签 is_risk（正样本率 0.32%）

close_df（销户表）

500 条销户记录：销户时间、原因

2.2 Agent 探索主循环

for round in 1..10:
    # 1. SHAP 反馈 → 计算各岛屿预算（薄弱维度多分配）
    budgets = compute_island_budgets(shap_importance)

    # 2. 遍历 4 个岛屿
    for island in [金额频次, 时间地域, 行为序列, 主体关联]:
        for turn in 1..3:   # 岛屿内最多3轮对话
            # LLM 生成候选特征 → L1/L2/L3 验证
            accepted, failed = run_island_turn(island, budgets[island])
            if accepted > 0 or turn >= 2: break

    # 3. 轮末：缓刑池前向选择
    pending_pool_evaluation()   # 基线 = 当前 existing_features 的真实指标

    # 4. 收敛检测
    if 连续2轮无新特征: 终止

2.3 existing_features 动态更新

关键设计：existing_features 是动态增长的特征矩阵。初始为 95 个基线特征，每当一个新特征通过 L3 验证或被缓刑池 FS 接受，立即加入。所有后续的 L3 增量评估、FS 基线计算、SHAP 反馈训练都基于最新的 existing_features。

举例：Round 1 接受了 2 个特征 → Round 2 的所有 L3 和 FS 都在 97 个特征的基础上评估。

3. 岛屿探索策略

3.1 四个探索维度（岛屿）

岛屿 维度 ID 关联字段 探索方向
金额频次 amount_frequency amount, interval, hour, transaction_motif 金额分布异常、交易频率模式、整数金额比例等
时间地域 time_region timestamp, src_ip, dst_ip, region_code, hour 夜间交易、IP 多样性、地域异常、时间集中度等
行为序列 behavior_sequence timestamp, transaction_mode, zs_timestamp, zs_channel 交易模式转移、序列自相关、收支不平衡等
主体关联 entity_association wallet_open_cert, wallet_open_tel, src_device, dst_device 设备共享、身份复用、交易网络结构等

3.2 SHAP 反馈驱动的预算分配

每轮开始时，系统在当前 existing_features 上训练 XGBoost 并计算全局 SHAP 重要性，按反比分配各岛屿的候选名额：

  • 薄弱维度（SHAP 贡献低）→ 分配更多名额（最多 5 个）
  • 饱和维度（SHAP 贡献高）→ 分配更少名额（最少 1 个）
  • 总预算：每轮 12 个候选，各岛屿范围 [1, 5]
weight[dim] = 1.0 / (importance[dim] + eps)
budget[dim] = clamp(weight[dim] / sum(weights) * 12, min=1, max=5)

3.3 岛屿内多轮对话

每个岛屿最多进行 3 轮对话（intra-island turns）：

  • 第 1 轮：提供完整的系统 prompt + 领域知识 + 种子代码示例，让 LLM 生成候选特征
  • 后续轮：提供上一轮的 SHAP 分析、失败特征原因、高分特征示例作为反馈
  • 如果某轮有特征被接受，或已完成 2 轮，则停止该岛屿的探索

4.1 L1：沙盒执行验证

目标：确保代码可安全执行，输出格式正确
  • 安全检查：AST 解析，禁止 os、sys、subprocess、open、eval 等危险操作
  • 允许的库：pandas, numpy, scipy, sklearn, datetime, collections, math
  • 执行方式：独立进程 + 90 秒超时
  • 输出校验：必须包含 wallet_id 或 tx_id，特征列非空，NaN < 50%，nunique > 1
  • 自动修复：执行失败时，最多调用 LLM 2 次自动修复代码

4.2 L2：统计质量验证

目标：确保特征有区分力、低冗余、低缺失
指标含义阈值说明
IV (Information Value) 特征对标签的区分能力 ≥ 0.001 基于分箱的正负样本分布差异
KS 正负样本累积分布的最大分离度 ≥ 0.001 越高说明特征越能区分正负样本
冗余度 与已有特征的最大 |Pearson 相关系数| < 0.7 避免与已有特征高度重复
缺失率 NaN 值比例 ≤ 0.5 缺失过多的特征不可用

注：IV 和 KS 阈值会在实验开始时通过噪声基准校准（生成 100 个随机噪声特征，取其分布的某个分位数作为下限），确保阈值适应当前数据集。

4.3 L3：模型增量验证

目标：确保新特征能提升模型 Recall，且不显著损害 Precision

评估方式：5 折交叉验证（StratifiedKFold），在每折训练集上寻找最优 F1 阈值，然后在验证集上评估。

增量对比：分别训练两个 XGBoost 模型：

  • 基线模型：仅使用当前 existing_features
  • 增强模型：使用 existing_features + 新特征

计算 delta_recall、delta_f1、delta_precision 以及 aug_precision（增强模型的绝对 Precision）。

L3 接受条件（Recall 优先）：
  1. delta_recall > 0 — Recall 必须提升（不可降低）
  2. aug_precision ≥ 0.95 — 加入新特征后 Precision 绝对值不低于 95%

F1 不设约束——只要 Recall 提升且 Precision 在安全线之上即可接受。

通过 L3 → 特征立即加入 existing_features，后续评估基线自动更新。

未通过 L3（但已通过 L2）→ 进入缓刑池（Pending Pool），等待组合评估。

4.4 L3 附加指标：SHAP Rank

每个通过 L2 的特征还会计算 SHAP 重要性排名（在所有 existing_features + 新特征上训练 XGBoost，排 mean |SHAP|）。此排名用于复合打分，不参与 L3 接受/拒绝判定。

5. 缓刑池与前向选择（FS）

5.1 缓刑池（Pending Pool）

通过 L2 但未通过 L3 的特征不会被直接丢弃，而是进入缓刑池等待组合效应评估。

参数值说明
最大容量20超出时淘汰互信息最低的特征
最大年龄3 轮超过 3 轮未被接受则清除
最大连续拒绝2 次连续 2 轮被 FS 拒绝则清除

5.2 前向选择（Forward Selection）

每轮所有岛屿探索结束后，对缓刑池中的候选特征执行贪心前向选择：

# 前向选择流程
X_current = existing_features   # 当前所有已接受的特征（动态）
current_metrics = compute_cv_metrics(X_current, y)  # 真实当前基线

while 还有候选:
    best = None
    for candidate in remaining_candidates:
        X_try = X_current + candidate
        m = compute_cv_metrics(X_try, y)

        if delta_recall > 0 and m["precision"] >= 0.95:
            score = delta_recall + 0.3 * delta_f1
            if score > best_score:
                best = candidate

    if best is None: break
    X_current += best
    current_metrics = best_metrics
FS 接受条件与 L3 一致：delta_recall > 0 且 precision ≥ 0.95。
排序依据：delta_recall + 0.3 × delta_f1（Recall 主导，F1 辅助）。

5.3 L3 与 FS 的区别

L3 验证FS 前向选择
触发时机 每个特征生成后立即评估 每轮结束时批量评估缓刑池
评估方式 单特征增量：加/不加这一个特征 组合贪心：逐步选最优组合
解决的问题 这个特征单独加进去有没有用？ 这些单独看不够好的特征，组合起来有没有用？
基线 当前 existing_features（动态） 当前 existing_features（动态，含 L3 新通过的）
接受条件 delta_recall > 0, aug_precision ≥ 95% 相同
为什么需要 FS？例如特征 A 单独加入使 Recall 下降 0.001（L3 拒绝），但特征 A+B 一起加入使 Recall 提升 0.003。L3 无法发现这种组合效应，FS 可以。

6. 领域知识注入

系统通过 prompt 向 LLM 注入大量反洗钱领域知识，显著提高特征生成的针对性：

交易模式知识（8种 Motif）

3 种正常模式 + 5 种异常模式，每种包含金额特征、时间间隔、交易方式、适用钱包类型等详细描述。

  • 正常：single_transaction, normal_small_high_freq, regular_large_low_freq
  • 异常：small_amount_testing, merchant_laundering, class4_laundering, online_laundering, victim_laundering
专家访谈（309份判决书）

从法院判决书中提取的 7 种洗钱模型：薅羊毛、线下跑分、线上跑分、商户收款码跑分等。包含转账链条模式、典型操作流程、佣金特征、关键行为签名、时间特征、组织层级等 9 个维度的深度分析。

风险指标（38个）

按维度组织的风险指标体系：金额、时间、IP、设备、身份、行为、交易模式等。每个指标标注风险类型、数据类型、方向。

检测规则（15条）+ 代码示例

现有的检测规则及其逻辑。系统自动将其中 2 条规则转换为 Python 代码示例，作为 LLM 的参考模板（如休眠账户激活、商户异常流量检测）。

额外注入信息

  • 数据库 Schema：三张表的完整字段描述
  • 分布差异：正常 vs 异常交易在各字段上的分布对比
  • Join 统计：表间关联关系和匹配率
  • 已有基线特征列表：避免 LLM 生成重复特征
  • 失败记忆：之前失败的特征名和原因，避免重蹈覆辙

7.2 评估指标

  • Recall（召回率）：最核心指标，衡量检出异常交易的能力
  • Precision（精确率）：衡量误报率，绝对值需 ≥ 95%
  • F1：Recall 和 Precision 的调和均值
  • PR-AUC：精确率-召回率曲线下面积

7.3 阈值优化

不使用固定 0.5 阈值。在每折训练集上遍历 0.05~0.95（步长 0.01），选择使 F1 最大化的阈值，然后用该阈值在验证集上计算 Recall、Precision。

7.4 SHAP 兼容性

XGBoost 3.2 GPU 模型的 base_score 以带方括号字符串返回（如 '[1.4586365E-1]'），shap 0.49.1 无法解析。系统通过 src/compat.py 中的 safe_tree_explainer() 自动修复：在创建 TreeExplainer 前清理 base_score 格式，确保全程使用真正的 SHAP 值而非 fallback 到 gain-based importance。

8. 特征复合打分

每个被接受的特征会计算一个综合分数，用于排序和展示（不影响接受/拒绝判定）：

维度权重计算方式
SHAP 排名30%1/rank（排名越高，分数越高）
IV 值20%原始 IV 值
冗余度20%1 - redundancy（越低越好）

四个维度分别做 Min-Max 归一化（基于历史所有被评估特征的分值），然后加权求和。

9. 收敛检测与终止条件

  • 正常终止：完成 10 轮迭代
  • 收敛终止：连续 2 轮没有新特征被接受（L3 + FS 均无产出）→ 提前终止

终止后执行最终的缓刑池评估（final pending pool evaluation），给剩余候选最后一次机会。

10. 可解释性生成

每个通过验证的特征，系统自动调用 LLM 生成可解释性报告，包含：

  • value_meaning：特征值的业务含义
  • risk_threshold：风险阈值建议
  • synergy：与其他特征的协同效应
  • false_positive_cases：可能的误报场景
  • regulatory_explanation：监管解释（满足反洗钱合规要求）
