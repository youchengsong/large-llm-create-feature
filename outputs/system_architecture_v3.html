1系统概述与设计理念

本系统利用大语言模型（DeepSeek）在数字人民币交易数据上自动发现反洗钱检测特征。系统将特征空间按业务维度分组，通过 SHAP 反馈动态调整各组的探索力度，使用三级验证流水线（L1 代码安全 → L2 统计质量 → L3 模型增量）过滤候选特征，并通过前向选择（Forward Selection）挖掘特征间的组合效应。

核心设计理念

Recall 优先

反洗钱场景中漏检代价远高于误报。所有验证条件以 Recall 提升为必要条件，Precision 只设绝对下限（95%），F1 不约束。

动态基线

每接受一个新特征，existing_features 立即更新。后续所有 L3 增量评估和前向选择都基于最新特征集，确保增量评估的准确性。

领域知识注入

将 309 份法院判决书洗钱模式、38 个风险指标、8 种交易模式、15 条检测规则等专家知识注入 LLM prompt，大幅提升特征生成的针对性。

组合效应捕获

单特征评估（L3）无法发现的互补效应，通过每轮末尾的前向选择从候选缓冲池中发掘。

4分组搜索策略

4.1 术语说明

本系统将特征空间按业务含义划分为 4 个维度组，每组聚焦不同的风险信号方向。这种分组设计借鉴了进化计算中的岛屿模型（Island Model）[1]的思路——将搜索种群分割为独立子群，各自进化后交换优秀个体——但在本系统中简化为按业务维度的分组搜索：每组有独立的候选预算和 LLM 对话上下文，组间通过 SHAP 反馈动态调整预算。

为什么分组？ 反洗钱特征涉及金额、时间、行为、关联等多个维度。如果不分组，LLM 容易集中在某一维度上反复生成相似特征。分组搜索保证每个维度都能得到探索，同时通过 SHAP 反馈让薄弱维度获得更多资源。

[1] Whitley, D., Rana, S., & Heckendorn, R. B. "The Island Model Genetic Algorithm: On Separability, Population Size and Convergence." Journal of Computing and Information Technology, 1999. 该策略也被 LLM-FE (Abhyankar et al., ICLR 2026 Workshop, arXiv:2503.14434) 应用于 LLM 驱动的特征搜索中。

4.3 组内多轮对话机制

每个维度组在每轮（Round）中最多进行 2 轮有效对话（配置上限为 3，但逻辑上第 2 轮后即退出）：

轮次行为退出条件
Turn 1 提供完整系统 prompt + 领域知识 + 种子代码示例，LLM 生成 N 个候选特征并逐个验证 如果有特征被 L3 接受 → 退出（已有收获）
如果没有失败特征 → 退出（LLM 无产出）
Turn 2 将 Turn 1 的失败原因、SHAP 分析、高分特征示例作为反馈注入 prompt，LLM 重新尝试 无论结果如何，Turn 2 结束后必定退出（turn ≥ 2 即 break）
为什么 Turn 2 后强制退出？ 实践发现超过 2 轮对话后，LLM 倾向于在相似方向上微调而非探索新思路。强制退出让系统进入下一个维度组，保证探索的广度。如果 Turn 1 已有特征被接受，说明该维度已有收获，无需继续。

4.4 预算（Budget）机制

每个维度组每轮被分配一个候选预算 N（由 SHAP 反馈驱动，详见第 9 节）。这个 N 控制的是LLM 在该维度组内需要生成并验证的候选特征数量。具体流程：

  1. LLM 生成候选特征代码（generate_feature）
  2. LLM 调用沙盒验证（execute_sandbox），触发 L1 → L2 → L3 验证链
  3. 当该组已验证的候选特征数达到 N（无论通过还是失败），该组的探索结束

其中 L1 有 2 次自动修复机会（代码执行失败时，LLM 自动修改代码重试），L2 和 L3 是单次评估，不重试。

5三级验证流水线 (L1 / L2 / L3)

5.1 L1：沙盒执行验证

目标：确保代码可安全执行，输出格式正确
检查项内容
安全检查AST 解析，禁止 os、sys、subprocess、open、eval 等危险操作
允许的库pandas, numpy, scipy, sklearn, datetime, collections, math
执行方式独立进程 + 90 秒超时
输出校验必须含 wallet_id 或 tx_id；特征列非空；NaN < 50%；nunique > 1
自动修复执行失败时，最多调用 LLM 2 次修复代码后重试

5.2 L2：统计质量验证

目标：确保特征有区分力、低冗余、低缺失
指标含义阈值
IV (Information Value)正负样本分布差异（分箱后计算）≥ 校准值（默认 0.001，基于噪声基准调整）
KS 统计量正负样本累积分布最大分离度≥ 校准值（默认 0.001）
冗余度与已有特征的最大 |Pearson 相关系数|< 0.7
缺失率NaN 值比例≤ 0.5

注：IV 和 KS 阈值在实验开始时通过噪声基准校准（生成 100 个随机噪声特征，取其分布的特定分位数作为下限），适应当前数据集特性。

5.3 L3：模型增量验证

目标：确保新特征能提升模型 Recall，且不严重损害 Precision

评估方式：5 折交叉验证（StratifiedKFold）。在每折训练集上搜索最优 F1 阈值（0.05~0.95），然后在验证集上评估。

增量对比（compute_delta_metrics）：

  • 基线模型：仅使用当前 existing_features（动态，含之前已接受的所有特征）
  • 增强模型：使用 existing_features + 新特征

两个模型在相同的 5 折拆分上训练和评估，计算 delta_recall、delta_f1、delta_precision 以及 aug_precision。

L3 接受条件（Recall 优先）：
  1. delta_recall > 0 — Recall 必须有提升（不可降低）
  2. aug_precision ≥ 0.95 — 加入新特征后 Precision 绝对值不低于 95%

F1 不设约束。只要 Recall 提升且 Precision 安全即可接受。

通过 L3

特征立即加入 existing_features。后续所有 L3 评估和前向选择的基线自动更新为包含该特征后的状态。

未通过 L3（但已通过 L2）

进入候选缓冲池，等待轮末前向选择评估组合效应。该特征可能单独无效但与其他特征组合后有效。

5.4 附加指标：SHAP Rank

每个通过 L2 的特征还会计算 SHAP 重要性排名（在 existing_features + 新特征上训练 XGBoost，排 mean |SHAP|）。此排名用于复合打分（第 10 节），不参与 L3 接受/拒绝判定。

6候选缓冲池

通过 L2 但未通过 L3 的特征进入候选缓冲池（Candidate Buffer），等待轮末前向选择评估其组合效应。这种"延迟评估"机制在 Wrapper-based 特征选择[2]中是常见做法：单特征评估可能遗漏交互效应，批量组合评估可以捕获。

参数值说明
最大容量20超出时淘汰互信息（MI）最低的特征
最大存活轮数3 轮超过 3 轮未被接受则清除
最大连续拒绝2 次被前向选择连续拒绝 2 轮则清除

生命周期

  1. 特征通过 L2 但 L3 失败 → 加入缓冲池
  2. 每轮结束时 → 前向选择评估所有候选
  3. 被选中 → 从缓冲池移除，加入 existing_features
  4. 被拒绝 → 连续拒绝计数 +1
  5. 轮次推进 → 年龄 +1，超龄或超拒清除

[2] Kohavi, R. & John, G. H. "Wrappers for Feature Subset Selection." Artificial Intelligence, 97(1-2), 273-324, 1997.

7前向选择 (Forward Selection)

前向选择（Forward Selection）是一种经典的 Wrapper 特征选择方法[2][3]：从空集开始，每轮贪心地加入使目标指标改善最大的特征，直到没有特征能满足接受条件。

7.1 本系统中的前向选择流程

每轮所有维度组探索结束后，对候选缓冲池中的特征执行贪心前向选择：

# 前向选择 (每轮末执行)
X_current = existing_features          # 当前所有已接受的特征（95 基线 + 已通过的新特征）
current_metrics = compute_cv_metrics(X_current, y)   # 计算真实当前基线指标

while 还有候选:
    best_candidate = None
    best_score = -inf

    for candidate in remaining_candidates:
        X_try = X_current + candidate
        m = compute_cv_metrics(X_try, y)     # 5-fold CV

        delta_recall = m["recall"] - current_metrics["recall"]

        if delta_recall > 0 and m["precision"] >= 0.95:
            score = delta_recall + 0.3 * (m["f1"] - current_metrics["f1"])
            if score > best_score:
                best_candidate = candidate
                best_score = score

    if best_candidate is None:
        break   # 没有候选能满足条件

    # 接受最佳候选，更新基线
    X_current += best_candidate
    current_metrics = compute_cv_metrics(X_current, y)

7.2 接受条件

与 L3 一致：delta_recall > 0 且 precision ≥ 0.95。

7.3 排序依据

当多个候选都满足条件时，选择 delta_recall + 0.3 × delta_f1 最大的。这是一个以 Recall 为主导、F1 为辅助的启发式排序。F1 的权重 0.3 确保在 Recall 提升相近时，优先选择 F1 也有提升的候选（即 Precision 损失更小的），但不会让 F1 反过来主导选择。

关于排序公式：这是一种多目标特征选择的启发式权重方案。在特征选择文献中，标准前向选择[3]通常使用单一指标排序。多目标排序常见于多目标优化领域[4]，通过加权和（Weighted Sum）将多个目标合并为标量是最简单的处理方式。本系统选择 Recall 权重 1.0、F1 权重 0.3 是基于业务优先级：Recall 是反洗钱的核心指标，F1 作为平衡指标起辅助参考作用。

7.4 L3 与前向选择的区别

L3 验证前向选择 (FS)
触发时机 每个特征生成后立即评估 每轮结束时，批量评估候选缓冲池
评估方式 单特征增量：加/不加这一个特征 组合贪心：逐步选最优组合
解决的问题 这个特征单独加进去有没有用？ 这些单独看不够好的特征，组合起来有没有用？
基线 当前 existing_features（动态） 当前 existing_features（动态，含本轮 L3 新通过的）
举例 特征 A 单独加入 → Recall -0.001 → L3 拒绝 A+B 组合 → Recall +0.003 → FS 接受 A 和 B

[3] Guyon, I. & Elisseeff, A. "An Introduction to Variable and Feature Selection." JMLR, 3, 1157-1182, 2003.
[4] Deb, K. "Multi-Objective Optimization Using Evolutionary Algorithms." Wiley, 2001.

8.2 阈值优化

不使用固定 0.5 阈值。在每折训练集上遍历 0.05~0.95（步长 0.01），选择使 F1 最大化的阈值，然后用该阈值在验证集上计算 Recall、Precision 等指标。

8.3 SHAP 兼容性处理

XGBoost 3.2 GPU 模型的 base_score 以带方括号字符串返回（如 '[1.4586365E-1]'），SHAP 0.49.1 无法解析。系统通过 src/compat.py 的 safe_tree_explainer() 在创建 TreeExplainer 前自动修复 base_score 格式，确保全程使用真正的 SHAP 值。

9SHAP 反馈与预算分配

每轮开始时，系统在当前 existing_features 上训练 XGBoost 并计算全局 SHAP 重要性。借鉴 MedFeat[5] 的思路，用 SHAP 值引导 LLM 的搜索方向。

9.1 反馈内容（注入 LLM Prompt）

  • Top 10 特征：归一化 SHAP 值最高的 10 个特征名和权重
  • 薄弱维度：SHAP 贡献低于均值的维度组

9.2 预算分配公式

按 SHAP 维度重要性的反比分配各组候选名额：薄弱维度获得更多探索资源。

weight[dim] = 1.0 / (importance[dim] + eps)        # eps = 0.01
budget[dim] = round(weight[dim] / sum(weights) * B_total)
budget[dim] = clamp(budget[dim], min=1, max=5)      # B_total = 12

[5] "MedFeat: Model-Aware and Explainability-Driven Feature Engineering with LLMs." arXiv:2603.02221, 2026.

11收敛检测与终止条件

  • 正常终止：完成 10 轮迭代
  • 收敛终止：连续 2 轮没有新特征被接受（L3 直接通过 + 前向选择 均无产出）→ 提前终止

终止后执行最终的候选缓冲池评估（Final Pending Pool Evaluation），给剩余候选最后一次机会。
