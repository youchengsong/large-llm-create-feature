一 问题定义

1.1 我们要解决什么问题

我们有一个数字人民币（e-CNY）反洗钱检测系统，当前已有人工设计的 40+ 个特征（见 inputs/baseline/feature_engineering.py）。这些特征存在已知缺口（多个数据字段未利用、时间窗口单一等），但人工逐一设计新特征效率低、容易遗漏。

核心思路：构建一个系统，让 LLM 自动发现新特征并生成可执行代码，同时为每个特征提供领域依据的可解释性说明。人不去设计特征，LLM 是特征工程师。

目标：用 LLM 自动发现人工未覆盖的新特征，每个新特征必须：

  1. 生成可直接执行的 Python 代码（不是文字描述或逻辑表达式）
  2. 附带可解释性说明（为什么创建这个特征、对应什么反洗钱领域知识）
  3. 经过验证确认有效（对下游模型有增量贡献）

1.2 预测目标

交易级二分类：每行 = 一笔交易，标签 = is_risk（0 或 1）。

依据：人工基线 feature_engineering.py 以交易表为主表，将 is_risk 作为 label。开户表的 is_abnormal 和销户表的 is_zs_laundering 是辅助信息，不是预测目标。

1.4 三表关联关系

交易表（主表，每行一笔交易）
  ├── src (wallet_id) ──→ 开户表.wallet_id → 获取发送方的账户属性
  │                   ──→ 销户表.wallet_id → 获取发送方的销户信息
  ├── dst (wallet_id) ──→ 开户表.wallet_id → 获取接收方的账户属性
  │                   ──→ 销户表.wallet_id → 获取接收方的销户信息

关联键是 wallet_id，交易表的 src 和 dst 字段都是 wallet_id。一个钱包可以出现在多笔交易中（作为 src 或 dst），所以是一对多关系。

二 参考文献与借鉴方式

本方案参考 6 篇论文，每篇借鉴特定组件。下面详细说明每篇论文的核心算法、我们具体借鉴什么、怎么用、为什么这样组合。

2.1 LLM-FE — 搜索引擎骨架

Abhyankar et al. “LLM-FE: Automated Feature Engineering for Tabular Data with LLMs as Evolutionary Optimizers.” ICLR 2026 Workshop. arXiv:2503.14434

论文做了什么：LLM-FE 把 LLM 当作进化优化器 — 维护多个“岛屿”（独立种群），每个岛屿保存一批特征转换程序。每轮从岛屿中选出高分程序作为 in-context 示例给 LLM，让 LLM 生成新程序。

核心算法：岛屿模型进化搜索

算法：岛屿模型进化搜索
参数：m=4 个岛屿, b=3 个候选/岛屿/轮, k=2 个 in-context 示例, τ=温度参数

初始化：每个岛屿 Island_j = {} (空集)

FOR round = 1 to T:
    选择一个岛屿 j（轮流或随机）

    # Boltzmann 采样选 in-context 示例
    IF Island_j 非空:
        对 Island_j 中每个程序 i，计算选择概率：
            P_i = exp(score_i / τ) / Σ_all exp(score_all / τ)
        从 P_i 分布中采样 k=2 个程序作为示例

    # LLM 生成新候选
    prompt = System_Prompt + 示例 + "请生成 b=3 个新特征转换"
    candidates = LLM(prompt) → 得到 b 个 Python 函数

    # 执行和评估
    FOR each candidate c in candidates:
        执行 c 在训练数据上 → 生成新特征列
        训练 XGBoost → 在验证集上评估 → score_c

    # 更新岛屿
    将 (candidate, score) 加入 Island_j

我们怎么用：

  • 完整采用岛屿模型和 Boltzmann 采样机制
  • 维度岛屿：原论文的岛屿是随机分组，我们按风险维度划分 4 个岛屿（见 2.7），每个岛屿有明确探索方向
  • 修改评估方式：原论文用 Accuracy，我们改为 PR-AUC
  • 扩展到多表：原论文仅支持单表输入，我们的 LLM 函数接收三个 DataFrame

论文实验数据：27 个 OpenML 数据集上排名 1.54（第一）。消融实验：去掉领域知识准确率 -26%，去掉进化精炼 -31%。

2.2 MedFeat — SHAP 导航系统

“MedFeat: Model-Aware and Explainability-Driven Feature Engineering with LLMs.” arXiv:2603.02221, 2026

论文做了什么：每轮特征生成后计算 SHAP 特征重要性，用 SHAP 值引导 LLM 下一轮的搜索方向。

核心算法：SHAP 引导的特征生成

FOR round t = 1 to T:
    # Step 1: 计算 SHAP 重要性
    model_t = 训练 XGBoost(当前特征集, y_train)
    shap_values = TreeExplainer(model_t).shap_values(X_val)
    s_t_i = mean(|shap_values[:, i]|)    # 全局平均绝对 SHAP 值
    s̃_t_i = s_t_i / Σ_all s_t_all       # 转为概率分布

    # Step 2: 构建 prompt 反馈
    shap_feedback = {
        "top_10_features": 按 s̃_t_i 排序的前10个特征及其重要性,
        "weak_dimensions": SHAP 值低的特征类别,
        "model_type": "XGBoost"
    }

    # Step 3: LLM 生成
    candidates = LLM(System_Prompt + shap_feedback + memory)

    # Step 4: 特征接受条件
    IF L_t_k* >= L_t_baseline + β (β=0.01):
        接受 candidate_k*，更新特征集和 baseline
    ELSE:
        拒绝，记录原因到失败记忆库

我们怎么用：完整采用 SHAP 引导机制、接受条件 β=0.01、失败记忆、模型感知。不采用它的搜索方式（单线迭代太慢），用 LLM-FE 的岛屿并行替代。

论文实验数据：去掉 SHAP 引导 F1 下降 9-26%，去掉模型感知 F1 最高下降 35.9%。

2.3 CAAFE — 代码安全与错误反馈

Hollmann et al. “Large Language Models for Automated Data Science: Introducing CAAFE.” NeurIPS 2023. arXiv:2305.03403

我们借鉴的具体机制：

代码安全白名单（借鉴 CAAFE）：
  允许的模块: pandas, numpy, scipy.stats, sklearn.preprocessing
  禁止的操作: os, sys, subprocess, open(), exec(), eval(), 网络请求

错误反馈循环（借鉴 CAAFE）：
  IF 代码执行失败:
      error_msg = 捕获的异常信息（类型 + 行号 + 消息）
      retry_prompt = f"你上一次生成的代码执行失败：\n{error_msg}\n请修正并重新生成。"
      corrected = LLM(retry_prompt)
      最多重试 2 次

输出格式（借鉴 CAAFE）：
  每个特征必须附带文本解释，说明为什么创建、捕捉了什么模式、对应哪个领域知识

论文实验数据：14 个数据集中 11 个获得提升，平均 ROC AUC +2.4%。

2.4 OCTree — 可解释性增强（可选）

Nam et al. “OCTree: Optimized Feature Generation via LLMs with Decision Tree Reasoning.” NeurIPS 2024. arXiv:2406.08527

训练浅层决策树 CART(max_depth=4)，将决策树分裂规则转为自然语言反馈给 LLM。作为 SHAP 反馈的可选补充。

论文实验数据：加入决策树反馈后，改进幅度从 1.4-17.2% 提升到 2.6-20.1%。

2.5 CoFEH — 后续升级方向

Xu et al. “CoFEH: LLM-driven Feature Engineering Empowered by Collaborative Bayesian HPO.” ASPLOS 2026. arXiv:2602.09851

用 MCTS 替代进化搜索，同时联合优化特征工程和模型超参数。实现复杂度最高，作为 V2 升级方向。

论文实验数据：排名 1.75（仅次于 LLM-FE 的 1.54）。

2.6 Balek 2025 — 统计验证方法

Balek et al. “LLM-based Feature Generation from Text for Interpretable ML.” Machine Learning, 2025. arXiv:2409.07132
Bootstrap 卡方检验（验证特征有效性）：
  FOR i = 1 to 2500:
      sample = 有放回抽样(feature, label)
      chi2_i, p_i = chi2_contingency(crosstab(sample_feature, sample_label))
  p_value = mean(所有 p_i)
  IF p_value < 0.05: 特征与标签显著相关

Cramer's V（衡量效应大小，不受样本量影响）：
  V = sqrt(χ² / (N × (min(r,c) - 1)))
  解释：V < 0.10 可忽略, 0.10-0.30 弱, 0.30-0.50 中等, > 0.50 强
关键发现：五篇论文（LLM-FE, CAAFE, MedFeat, OCTree, CoFEH）无一使用统计检验。我们用 Balek 的方法填补这个缺口。

3.4 三表关联模块的具体实现

LLM 生成的特征函数支持两种返回粒度，系统自动处理：

def merge_feature_to_transactions(feature_df, tx_df):
    """将 LLM 生成的特征合并到交易表"""

    if 'tx_id' in feature_df.columns:
        # 交易级特征：直接 merge
        return tx_df.merge(feature_df, on='tx_id', how='left')

    elif 'wallet_id' in feature_df.columns:
        # 钱包级特征：分别 merge 到 src 和 dst
        feature_name = [c for c in feature_df.columns if c != 'wallet_id'][0]

        # src 侧
        src_df = feature_df.rename(columns={
            'wallet_id': 'src',
            feature_name: f'{feature_name}_src'
        })
        tx_df = tx_df.merge(src_df, on='src', how='left')

        # dst 侧
        dst_df = feature_df.rename(columns={
            'wallet_id': 'dst',
            feature_name: f'{feature_name}_dst'
        })
        tx_df = tx_df.merge(dst_df, on='dst', how='left')

        return tx_df

四 系统架构详细设计

4.1 总体流程

Phase 0: 输入准备
三表加载 → Schema 提取 → 基线特征 → 领域知识
Phase 1-2: 进化搜索循环（核心）
4 维度岛屿 → Boltzmann 采样 → LLM 生成 → L1-L3 验证 → SHAP 反馈
Phase 3: 最终验证与产出
L4 稳定性 → 5 组实验 → 特征字典 → 可视化报告

Phase 1-2 搜索循环的详细步骤：

FOR round = 1 to T (最多 10 轮):

  --- Step 1: 生成候选特征 ---
      4 个维度岛屿各自:
      - Boltzmann 采样选 k=2 个 in-context 示例
      - 构建 User Prompt（SHAP反馈 + 维度引导词 + 示例 + 失败记录）
      - 调用 LLM 生成 b=3 个候选特征
      → 本轮共 4x3 = 12 个候选特征

  --- Step 2: 代码执行与安全检查 ---
      对每个候选:
      - 安全白名单检查（禁止 os/sys/网络等）
      - 在沙盒中执行（超时 30s, 内存 2GB）
      - 检查输出: 非空、非全0、非全1、无 NaN 超过 50%
      - 失败的: 错误信息反馈给 LLM 重试（最多 2 次）

  --- Step 3: 特征质量评估 ---
      L2 统计验证:
      - 互信息 MI(feature, label) > 0.01
      - |corr| < 0.9（非冗余）
      - Cramer's V > 0.05

      L3 模型验证:
      - 训练 XGBoost, 5折分层CV
      - deltaPR-AUC ≥ 0.005

      综合打分:
      score = 0.35*SHAP_rank + 0.25*MI + 0.25*(1-冗余度) + 0.15*deltaPR-AUC

  --- Step 4: 记忆更新与反馈 ---
      接受的特征 → 加入岛屿记忆库
      拒绝的特征 → 加入失败记忆库
      岛屿间迁移: 本轮最高分特征复制到所有岛屿
      SHAP 反馈: top-10 特征 + 弱势维度

  收敛判断: 连续 2 轮无新特征通过 → 停止

4.2 LLM 输出格式

每个候选特征，LLM 需要输出以下 JSON 结构：

{
    "feature_name": "night_fan_out_ratio",
    "granularity": "wallet",
    "rationale": "邮储专家指出线上跑分常在凌晨进行，且呈现'分散转出'模式...",
    "knowledge_source": "邮储专家访谈-线上跑分模式 + 可疑交易识别点1-1",
    "code": "def compute_feature(open_df, tx_df, close_df):\n    ..."
}

字段说明：feature_name（描述性特征名）、granularity（wallet 或 transaction）、rationale（可解释性说明，必须引用领域知识）、knowledge_source（引用来源）、code（可执行 Python 函数）。

4.3 Prompt 详细设计

System Prompt（固定，约 5000 token）
  • 角色设定：「你是数字人民币反洗钱领域的特征工程师」
  • 输出格式：JSON 数组，每个特征包含 feature_name、granularity、rationale、knowledge_source、code
  • 数据结构：三表完整 schema（字段名 + 类型 + 统计摘要）+ 三表关联说明
  • 领域知识：8 种交易模式说明 + 4 类洗钱模式（专家访谈）+ 38 个风险指标 + 36 条核心识别点
  • 已有特征列表：107 个基线特征名（告诉 LLM 不要重复）
  • 约束条件：30 秒超时、白名单库、禁用标签列、仅 Python 代码
User Prompt（每轮变化）

第 1 轮（冷启动）：当前岛屿名称 + 重点字段 + 检测规则转化的种子示例代码

第 2+ 轮（迭代）：增加以下动态信息：

  • 上轮最佳特征（从记忆库中 Boltzmann 采样的高分示例）
  • SHAP 反馈（当前哪些特征最重要、哪些维度薄弱）
  • 失败记忆（上轮失败的特征及原因，避免重复犯错）
  • 多轮岛内对话：每个岛屿最多 3 轮对话，实时反馈验证结果
  • 数据查询结果：LLM 上轮发起的统计查询结果

4.4 SHAP 与岛屿进化的融合细节

每一轮迭代的执行流程：

1. SHAP 分析（全局，所有岛屿共享）
   model = XGBoost(当前全部特征)
   shap_values = TreeExplainer(model).shap_values(X_val)
   shap_feedback = 生成 top-10 特征 + 弱势维度文本

2. 对每个维度岛屿 j ∈ {金额频次, 时间地域, 行为序列, 主体关联}：

   a) Boltzmann 采样选 in-context 示例（岛屿独立）
      P_i = exp(score_i / τ) / Σ exp(score_all / τ)
      示例 = 从 P_i 分布中采样 k=2 个特征

   b) 构建 User Prompt
      = 维度引导词（岛屿专属）
      + shap_feedback（全局共享）
      + 示例（岛屿独立的 Boltzmann 采样结果）
      + 失败记忆（全局共享）

   c) 调用 LLM 生成 b=3 个候选

3. 岛屿间迁移
   best_feature = 本轮所有 12 个候选中得分最高的
   复制到所有岛屿的记忆库（跨维度经验共享）
为什么这样设计：维度划分让每个岛屿有明确方向；SHAP 全局共享让所有岛屿知道哪个方向有价值；Boltzmann 岛屿独立保持多样性；迁移最优实现跨维度好特征传播。

六 特征有效性验证方法

6.1 四级验证框架

每个 LLM 生成的候选特征经过四级验证，逐级过滤。只有通过全部四级的特征才进入最终特征集。

L1: 代码验证
安全白名单 → 隔离执行(30s) → 输出格式 → 数据质量
L2: 统计验证（阈值自动校准）
MI ≥ auto & Redundancy < 0.9 & Cramer's V ≥ auto & Bootstrap p < 0.05
L3: 模型验证
ΔPR-AUC ≥ 0.005 & SHAP 排名
L4: 稳定性验证
10次 Bootstrap → Nogueira 稳定性 > 0.8

L1: 代码验证（来自 CAAFE）

检查项通过条件失败处理
安全白名单仅使用 pandas/numpy/scipy/sklearn直接拒绝
执行成功30s 内无异常退出错误信息反馈 LLM 重试（最多2次）
输出格式返回 DataFrame，含 wallet_id 或 tx_id 列反馈格式要求
数据质量非全 0、非全 1、NaN < 50%拒绝并记录

L2: 统计验证（来自 Balek）

# 互信息检验
from sklearn.feature_selection import mutual_info_classif
mi = mutual_info_classif(feature.values.reshape(-1,1), label, random_state=42)[0]
assert mi > 0.01, "特征与标签的互信息过低"

# 冗余度检验
for existing in existing_features:
    corr = abs(feature.corr(existing))
    assert corr < 0.9, f"与已有特征 {existing.name} 相关系数 {corr:.3f} 过高"

# Cramer's V
V = np.sqrt(chi2 / (len(feature) * (min(contingency.shape) - 1)))
assert V > 0.05, "Cramer's V 过低"

# Bootstrap 卡方检验（2500次）
assert np.mean(p_values) < 0.05, "Bootstrap卡方检验不显著"
L2 阈值自动校准

src/evaluation/calibration.py

  1. 对基线特征分别计算 MI 和 Cramer's V
  2. 取各指标的 p10 分位数 × 0.5 作为新阈值
  3. 冗余度和 Bootstrap p 保持不变

核心思想：新特征只需不比最弱的基线特征差太多即可通过 L2 粗筛。最终质量由 L3 + 反向淘汰把关。

L3: 模型验证（来自 MedFeat）

Delta PR-AUC（增量 PR-AUC）

通过 XGBoost 5 折分层交叉验证对比。阈值：ΔPR-AUC ≥ 0.005。

为什么用 PR-AUC 而不是 ROC-AUC？

AML 数据正样本 ~5%，ROC-AUC 过度乐观。PR-AUC 更能反映模型找到真正可疑交易的能力。

论文评估指标对 AML 场景的问题
LLM-FEAccuracy全预测负可达 95%，完全无用
CAAFEROC AUC过度乐观，FPR 分母太大
MedFeatAUC + F1AUC 同上，F1 依赖阈值选择
OCTree错误率同 Accuracy 问题
CoFEH错误率同 Accuracy 问题

L4: 稳定性验证

# 在最终特征集确定后执行（不在搜索循环中）
stability_results = []
for _ in range(10):
    X_boot, y_boot = resample(X_final, y, stratify=y)
    model = xgb.XGBClassifier(scale_pos_weight=19)
    model.fit(X_boot, y_boot)
    shap_values = shap.TreeExplainer(model).shap_values(X_boot)
    importance_rank = np.argsort(-np.mean(np.abs(shap_values), axis=0))
    stability_results.append(importance_rank[:20])

# Nogueira 稳定性指数 > 0.8
stability_index = compute_nogueira_stability(stability_results)

九 核心创新点（论文贡献）

1. 领域知识增强

首次将结构化专家知识（访谈 + 200+ 识别点 + 监管规则）和数据集交易模式说明系统性注入 LLM 特征生成流程。现有方法（LLM-FE、CAAFE、MedFeat）都缺乏深度领域知识注入。

2. 多表关联

首次将 LLM 特征工程扩展到多表关系型数据（开户 + 交易 + 销户三表）。所有 6 篇参考论文均仅支持单表输入。

3. 维度岛屿 + SHAP 搜索

改进 LLM-FE 的随机岛屿为按风险维度划分的 4 个岛屿，结合 MedFeat 的 SHAP 引导，实现有分工 + 有方向的高效搜索。

4. 四级验证框架

代码验证 → 统计验证 → 模型验证 → 稳定性验证，超越现有论文（无一使用统计检验）的验证深度。

5. 可解释特征

每个特征附带领域依据说明和知识来源引用，满足金融监管的可解释性要求。

6. 缓刑池反向淘汰

解决特征组合效应问题。现有方法（CAAFE、LLM-FE）均逐个评估，无法捕捉交互。

7. L2 阈值自动校准

验证阈值从基线特征分布自动校准（p10 × 0.5），解决固定阈值过严导致搜索失败的问题。

10.3 中等风险（需重点关注）

风险 1：LLM 代码生成质量 — 最大的不确定性
  • 三表数据较复杂：LLM 需理解 src/dst 都是 wallet_id、需要 groupby + merge，比单表难很多
  • 之前 458 条规则全部失败：虽然原因已解决（无 schema + 无执行验证），但说明任务难度不低
  • 缓解措施：错误反馈重试（最多 2 次）+ 种子规则做示例 + 约束列表
  • 建议：第 1 轮先手动跑 3-5 个候选，看实际输出质量
风险 2：PR-AUC 增量阈值可能过严或过松
  • deltaPR-AUC ≥ 0.005 在模拟数据上是否合适不确定
  • 如果人工基线已 0.90+，0.005 的增量可能太严；如果只有 0.60，又太松
  • 建议：先跑一次基线 PR-AUC，再决定阈值
风险 3：综合打分公式的量纲问题
  • 四个指标量纲不同，不归一化会被 SHAP_rank 主导
  • 建议：对每个指标做 min-max 归一化到 [0,1]，然后再加权
# SHAP_rank 需要反转（排名越小越好 -> 归一化后越大越好）
shap_norm = 1 - normalize_score(shap_rank, all_shap_ranks)
mi_norm = normalize_score(mi, all_mi_values)
redundancy_norm = 1 - max_corr
prauc_norm = normalize_score(delta_prauc, all_delta_praucs)
score = 0.35 * shap_norm + 0.25 * mi_norm + 0.25 * redundancy_norm + 0.15 * prauc_norm

附录 A 缓刑池与综合评分

单独的增量验证（L3）会遗漏需要组合才能发挥作用的特征。缓刑池机制解决这个问题：

L2 通过 + L3 未通过
统计上有信号，但单独增量不够
进入缓刑池
最多 20 个，记录 age 和 consecutive_rejects
每轮末反向淘汰
全量加入 → SHAP 排序 → 从弱到强逐个剔除

反向淘汰流程

  1. 构造完整矩阵：已接受 N 个 + 缓刑池 M 个 = N+M 列
  2. 训练 + SHAP：XGBoost 5 折 CV 得到 score_full，算 SHAP 重要性
  3. 逐个剔除：从 SHAP 最低的缓刑池特征开始：
    • 剔除后分数不降 → 确认没贡献，标记为 rejected
    • 剔除后分数下降 → 在组合中有贡献，保留并接受
为什么能捕捉组合效应？ 如果特征 A 和 B 单独无增量，但 A+B 在模型中产生交互，全量矩阵中 score_full 包含了 A+B 的组合增益。尝试剔除 A 时分数下降（因为失去搭档），A 被保留。

淘汰规则

情况处理
本轮未被剔除接受，移入已接受特征集
被剔除，consecutive_rejects < 2 且 age ≤ 3留在池中等下轮
连续被剔除 ≥ 2 次永久淘汰
age > 3 轮永久淘汰
池中超过 20 个按 MI 分数淘汰最弱的

综合评分机制

src/evaluation/validator.py — compute_composite_score()

Score = 0.35 × norm(1/SHAP_rank) + 0.25 × norm(MI) + 0.25 × norm(1-redundancy) + 0.15 × norm(ΔPR-AUC)
指标权重含义
1/SHAP_rank0.35在模型中的重要性（权重最高，直接反映对预测的贡献）
MI0.25与标签的信息量相关性
1-redundancy0.25与已有特征的非冗余程度
ΔPR-AUC0.15模型增量贡献
