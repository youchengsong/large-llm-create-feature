概述 系统总览与核心思想

本系统利用大语言模型（LLM）自动为数字人民币反洗钱检测模型发现新特征。核心思想可以用一句话概括：

让 LLM 充当特征工程师 — 给它领域知识和数据 schema，让它生成 Python 特征提取代码，再通过严格的三级验证筛选出真正有效的特征。

传统做法是人工专家根据经验设计特征，但这种方式受限于个人知识和经验。本系统将这一过程自动化：

  • 输入：数据表结构（schema）+ 领域知识（专家访谈、检测规则、风险指标）
  • 引擎：LLM 在 4 个维度岛屿上迭代搜索，每轮生成候选特征代码
  • 过滤：L1→L2→L3 直通验证 + 缓刑池反向淘汰（捕捉特征组合效应）
  • 数据探索：LLM 可主动查询数据统计（按需探索 + 预计算注入）
  • 输出：经过验证的特征 Python 代码 + 可解释性说明 + 评估指标
关键设计原则
  • 数据不入 LLM — LLM 只看到 schema 元信息（字段名、类型、统计摘要），原始账户和交易数据不会发送给 LLM
  • 代码隔离执行 — LLM 生成的代码在受限沙盒中运行，禁止文件 I/O、网络访问等危险操作
  • 统计严格验证 — 每个候选特征必须通过互信息、冗余度、卡方检验和模型增量贡献四重检验
  • SHAP 反馈引导 — 用已接受特征的 SHAP 重要性引导 LLM 的后续搜索方向

架构 整体架构与数据流

完整 pipeline 分为 4 个阶段，下图展示了从原始数据到最终特征产出的全流程：

Phase 0: 数据准备
三表加载 → Schema 提取 → 基线特征 → 领域知识
Phase 1: LLM 特征生成
Prompt 组装 → 4 维度岛屿搜索 → Boltzmann 采样 → SHAP 反馈
Phase 2: 三级验证
L1 沙盒执行 → L2 统计检验 → L3 模型增量 → 综合打分
Phase 3: 最终验证与产出
L4 稳定性 → 5 组实验 → 特征字典 → 可视化报告

Phase 0 数据准备与基线构建

Phase 0 的目标是准备 LLM 搜索所需的全部输入材料。这个阶段完全不涉及 LLM，是纯数据工程。

Step 1: 加载三张数据表

src/data/loader.py — load_all_tables()

系统基于数字人民币场景的三张核心表：

表名粒度字段数核心字段
开户表 (open_df) 每行 = 一个钱包 16 wallet_id, wallet_type, wallet_level, wallet_open_cert (身份证), wallet_open_tel (手机号), region_code, open_device, open_ip
交易表 (tx_df) 每行 = 一笔交易 20 tx_id, src (发送方), dst (接收方), amount, timestamp, hour, transaction_mode, is_risk (标签)
销户表 (close_df) 每行 = 一次销户 5 wallet_id, zs_channel (销户渠道), zs_timestamp
为什么是三表而不是单表？

反洗钱检测需要从多个角度观察：开户信息揭示身份特征（同一身份证开多个钱包），交易信息揭示行为模式（金额、时间、网络结构），销户信息揭示生命周期异常（交易后快速销户）。三表关联才能捕捉完整的洗钱链路。这也是本系统的一个创新点 — 现有 LLM 特征工程论文全部只支持单表。

Step 2: Schema 提取

src/data/loader.py — extract_schema()

为每个字段生成统计摘要（类型、空值率、唯一值数、数值范围/分类频率），这些信息会注入 LLM Prompt，让 LLM 了解数据长什么样：

# 示例 schema 输出
=== 开户表(accounts) (1000 rows, 16 columns) ===
  wallet_id: object | null=0.0% | unique=1000 | top: W0001(1), W0002(1)...
  wallet_level: int64 | null=0.0% | unique=4 | min=1, median=3, max=4
  wallet_open_cert: object | null=42.3% | unique=573 | top: 110101...(3), ...
  amount: float64 | null=0.0% | min=0.01, median=500, max=50000

Step 3: 运行人工基线特征

src/data/baseline.py — run_baseline()

调用 inputs/baseline/feature_engineering.py 中人工设计的 107 个特征（如交易金额均值、夜间交易比例、出入度等），并用 XGBoost 5 折交叉验证计算基线 PR-AUC。

基线的意义：LLM 生成的新特征必须在此基础上产生增量贡献，而不是重新发明轮子。

Step 4: 加载领域知识

src/prompt/domain_knowledge.py

从多个来源收集领域知识，压缩后注入 LLM Prompt：

知识来源内容数量
交易模式说明3 种正常模式 + 5 种风险模式的特征描述8 种
专家访谈4 类洗钱模式（薅羊毛、线上跑分、对公跑分、对敲交易）4 类
风险分类表银行识别的风险指标（异常金额、异常时间等）38 个
检测规则现有反洗钱检测规则，转为 Python 代码示例15 条

Phase 1 LLM 特征生成

Phase 1 是系统的核心 — 利用 LLM 自动生成特征提取的 Python 代码。这不是简单的一次性调用，而是一个多轮迭代的进化搜索过程。

4.1 Prompt 工程

src/prompt/builder.py

Prompt 分为两部分，共同构成对 LLM 的完整指令：

System Prompt（固定，约 5000 token）
  • 角色设定：「你是数字人民币反洗钱领域的特征工程师」
  • 输出格式：JSON 数组，每个特征包含 feature_name、granularity、rationale、knowledge_source、code
  • 数据结构：三表的完整 schema（由 Phase 0 提取的字段名 + 类型 + 统计摘要）
  • 三表关联：说明 src/dst 如何关联到 wallet_id
  • 领域知识：交易模式 + 专家访谈 + 风险指标（压缩后的文本）
  • 已有特征列表：107 个基线特征名（告诉 LLM 不要重复）
  • 分布差异注入：正常 vs 异常交易的聚合统计差异（金额、时间间隔、凌晨占比等）
  • 三表关联统计：src/dst 匹配率、销户率、钱包重叠率
  • 基线代码示例：15 个代表性人工特征的实现代码
  • 思维链（CoT）：要求 LLM 先分析分布差异 → 匹配领域知识 → 检查非冗余 → 再写代码
  • 数据探索能力：LLM 可输出查询动作，在沙盒中执行统计查询
  • 约束条件：30 秒超时、白名单库、禁用标签列等
User Prompt（每轮变化）

第 1 轮（冷启动）：给出当前岛屿名称 + 重点字段 + 检测规则转化的种子示例代码

第 2+ 轮（迭代）：增加以下动态信息：

  • 上轮最佳特征（从记忆库中 Boltzmann 采样的高分示例）
  • SHAP 反馈（当前哪些特征最重要、哪些维度还薄弱）
  • 失败记忆（上轮失败的特征及原因，避免重复犯错）
  • 多轮岛内对话：每个岛屿最多 3 轮对话，实时反馈验证结果
  • 数据查询结果：如果 LLM 上轮发起了统计查询，结果会注入反馈

LLM 每次根据 SHAP 动态预算生成 1-5 个候选特征（JSON 格式），每个特征包含可执行的 Python 代码片段。

LLM 输出示例

[
  {
    "feature_name": "night_fan_out_ratio",
    "granularity": "wallet",
    "rationale": "线上跑分常在凌晨进行，呈现分散转出模式...",
    "knowledge_source": "邮储专家访谈-线上跑分模式",
    "code": "tx = tx_df.copy()\ntx['is_night'] = ..."
  },
  ...
]

4.2 维度岛屿搜索

src/search/island.py + src/config.py

受 LLM-FE 论文启发，搜索空间被划分为 4 个维度岛屿，每个岛屿专注于一类反洗钱特征：

金额频次

金额分布、交易频率、拆分交易

字段：amount, interval, hour, transaction_motif

时间地域

夜间交易、IP 跳变、跨地域

字段：timestamp, src_ip, dst_ip, region_code, hour

行为序列

休眠激活、交易对手更换、用途偏离

字段：timestamp, transaction_mode, zs_timestamp, zs_channel

主体关联

交叉转账网络、身份复用、设备共享

字段：wallet_open_cert, wallet_open_tel, src_device, dst_device, src, dst

每一轮搜索中，引擎依次遍历 4 个岛屿，总候选预算为 B_total=12。第 1 轮均匀分配（每岛 3 个），从第 2 轮开始根据 SHAP 维度重要性动态分配：薄弱维度的岛屿获得更多候选名额（最多 5 个），已饱和的岛屿减少（最少 1 个），使搜索资源向最需要探索的方向倾斜。

每个岛屿维护自己的记忆库（memory）：通过验证的特征会存入对应岛屿。同时，高分特征会通过 migrate_best() 迁移到所有岛屿，让跨维度的信息共享。

4.3 Boltzmann 采样

src/search/island.py — boltzmann_sample()

从记忆库中选择 in-context 示例时，不是简单地选最高分的，而是使用 Boltzmann（玻尔兹曼）采样：

P(i) = exp((scorei - max_score) / τ) / ∑ exp((scorej - max_score) / τ)

其中 τ (tau) 是温度参数，默认为 1.0：

  • τ → 0：退化为贪心选择（总是选最高分），容易陷入局部最优
  • τ → ∞：退化为均匀随机采样，失去引导性
  • τ = 1.0：平衡探索与利用 — 高分特征有更高概率被选中，但低分特征也有机会

默认每次采样 k=2 个示例，使用无放回加权采样避免重复选择同一个特征。

# Boltzmann 采样核心代码
scores = [f.get("score", 0.0) for f in self.memory]
max_score = max(scores)
weights = [math.exp((s - max_score) / tau) for s in scores]
total = sum(weights)
probs = [w / total for w in weights]
indices = _weighted_sample_without_replacement(probs, k)

4.4 SHAP 反馈闭环

src/search/shap_feedback.py

这是系统的核心创新之一。每一轮搜索后，系统会：

  1. 用当前所有已接受的特征训练一个 XGBoost 模型
  2. 用 SHAP TreeExplainer 计算每个特征的全局重要性
  3. 将 Top-10 重要特征和薄弱维度反馈给 LLM
薄弱维度检测：系统将每个特征的 SHAP 重要性映射到它所属的维度岛屿，计算各维度的总重要性。低于平均值的维度被标记为「薄弱」，引导 LLM 在下一轮优先探索这些方向。

反馈文本注入 User Prompt 后，LLM 能理解「当前模型缺什么」，从而生成更有针对性的特征。这形成了一个搜索 → 验证 → 反馈 → 搜索的闭环。

4.5 数据探索（A+B 方案）

src/data/loader.py + src/data/stats_query.py

LLM 获取数据信息有两条路径：

方案 A：预计算注入（被动）

在 System Prompt 中预先注入：

  • 分布差异：正常 vs 异常交易在金额/时间间隔/凌晨占比/交易模式等维度的聚合统计
  • 关联统计：src→开户表匹配率、dst→开户表匹配率、销户率、钱包重叠率
  • 覆盖约 10 个关键维度，不泄露原始数据
方案 B：按需查询（主动）

LLM 可在输出中使用查询动作：

{"action": "query", "question": "凌晨2-4点的金额分布", "code": "query_result = tx_df[tx_df['hour'].between(2,4)].groupby('src')['amount'].describe()"}
  • 代码在同样的安全沙盒中执行（15 秒超时）
  • 结果返回给下一轮对话（最多 2000 字符）
  • 每轮最多 3 个查询
  • 在多轮岛内对话的第 2 轮起可用

A 为主、B 为补充：A 保证基本质量（覆盖 80% 常见需求），B 解决后期深水区探索（LLM 自行决定需要什么信息）。

4.6 多轮岛内对话

src/search/engine.py

每个岛屿每轮不只调用一次 LLM，而是进行最多 3 轮对话（intra_island_turns=3）：

  1. Turn 1：正常生成候选特征 → L1/L2/L3 验证
  2. Turn 2：将 Turn 1 的验证结果（通过/失败及原因）+ 数据查询结果反馈给 LLM → 生成新候选
  3. Turn 3：同上，继续迭代

提前停止条件：如果某轮没有新特征通过且没有数据查询，后续轮次不再继续。

Phase 2 三级验证

LLM 生成的每个候选特征必须依次通过三级验证，任一级失败即被淘汰。这是保证特征质量的核心机制。

L1: 代码沙盒验证
安全检查 → 隔离执行 → 输出格式验证
L2: 统计验证
MI ≥ 0.001 & Redundancy < 0.9 & Cramer's V ≥ 0.05 & Bootstrap p < 0.05
L3: 模型验证
ΔPR-AUC ≥ 0.005 & SHAP 排名

5.1 L1: 代码沙盒验证

src/evaluation/sandbox.py

L1 回答的问题是：这段代码能不能安全正确地执行？

Step 1: AST 安全检查

用 Python AST 解析代码，检查所有 import 和函数调用：

  • 允许 pandas, numpy, scipy, sklearn
  • 禁止 os, sys, subprocess, socket, requests, pickle, ctypes...
  • 禁止 open(), exec(), eval(), __import__(), getattr()...
Step 2: 子进程隔离执行

通过 multiprocessing.Process 在独立进程中执行代码，设置 30 秒超时。数据通过 Parquet 文件传入（避免序列化开销），结果也通过 Parquet 返回。

运行环境中只暴露 open_df、tx_df、close_df、pd、np 五个变量。代码执行完毕后，从 result 变量取出结果 DataFrame。

Step 3: 输出格式验证
  • 必须包含 wallet_id 或 tx_id 列（用于后续 merge）
  • 必须包含至少一个特征列
  • 特征不能全为常数（全 0 或全 1 无区分度）
  • NaN 比例不能超过 50%
L1 失败重试机制

如果 L1 失败（代码报错），系统不会直接放弃，而是将错误信息反馈给 LLM，让它修复代码并重试，最多重试 2 次。这显著提高了特征的通过率。

特征 Merge 逻辑

src/data/merge.py

L1 通过后，特征需要 merge 到交易表上才能用于模型训练：

  • tx_id 级特征（如每笔交易的金额异常分数）：直接 merge on tx_id
  • wallet_id 级特征（如每个钱包的多身份证计数）：分别 merge 到交易的 src 和 dst，生成 feature_src 和 feature_dst 两列

5.2 L2: 统计验证

src/evaluation/validator.py + src/evaluation/metrics.py

L2 回答的问题是：这个特征在统计意义上和标签相关吗？

指标 含义 计算方法 阈值
互信息 (MI) 特征与标签的信息量共享程度 sklearn mutual_info_classif ≥ 0.001
冗余度 与已有特征的最大皮尔逊相关系数 逐列计算 |corr|，取最大值 < 0.9
Cramer's V 特征与标签的关联强度（分类变量版） 卡方统计量 → V = √(χ² / (n·k)) ≥ 0.05
Bootstrap χ² p 值 关联性是否具有统计显著性 2500 次 bootstrap 重采样取平均 p 值 < 0.05

四个条件必须同时满足才能通过 L2。连续特征在计算 Cramer's V 和 Bootstrap χ² 时会先进行 10 分位分箱。

为什么需要冗余度检查？ 如果新特征和已有特征高度相关（|corr| ≥ 0.9），即使它和标签相关，也不提供新信息。这确保每个通过的特征都是「增量」的。

5.3 L3: 模型验证

src/evaluation/metrics.py

L3 回答的问题是：加入这个特征后，下游模型真的变好了吗？

Delta PR-AUC（增量 PR-AUC）

通过 XGBoost 5 折分层交叉验证对比：

  1. 基线模型：只用已有特征训练 → 得到 PR-AUCbase
  2. 增强模型：已有特征 + 新特征训练 → 得到 PR-AUCaug
  3. ΔPR-AUC = PR-AUCaug - PR-AUCbase

阈值：ΔPR-AUC ≥ 0.005（即新特征至少带来 0.5% 的 PR-AUC 提升）

为什么用 PR-AUC 而不是 ROC-AUC？

反洗钱数据高度不平衡（正样本约 5%）。ROC-AUC 在不平衡场景下过度乐观 — 一个全预测负的模型 ROC-AUC 也能很高。PR-AUC（Precision-Recall 曲线下面积）更能反映模型找到真正可疑交易的能力。

SHAP 排名

通过 L3 后，还会计算新特征在完整模型中的 SHAP 重要性排名（1 = 最重要）。排名信息用于后续的综合打分和反馈。

XGBoost 训练参数专门为不平衡数据调优，支持 GPU 加速：

XGBClassifier(
    scale_pos_weight=19,    # 正样本权重提升 19 倍
    eval_metric="aucpr",     # 评估指标用 PR-AUC
    n_estimators=200,
    max_depth=6,
    learning_rate=0.1,
    tree_method="hist",      # 直方图加速算法
    device="cpu",            # 可通过 XGB_DEVICE 环境变量切换为 GPU
)

缓刑池 特征组合效应捕捉

单独的增量验证（L3）会遗漏需要组合才能发挥作用的特征。缓刑池机制解决这个问题：

L2 通过 + L3 未通过
统计上有信号，但单独增量不够
进入缓刑池
最多 20 个，记录 age 和 consecutive_rejects
每轮末反向淘汰
全量加入 → SHAP 排序 → 从弱到强逐个剔除

反向淘汰流程

  1. 构造完整矩阵：已接受 N 个 + 缓刑池 M 个 = N+M 列
  2. 训练 + SHAP：XGBoost 5 折 CV 得到 score_full，算 SHAP 重要性
  3. 逐个剔除：从 SHAP 最低的缓刑池特征开始：
    • 剔除后分数不降 → 确认没贡献，标记为 rejected
    • 剔除后分数下降 → 在组合中有贡献，保留并接受
为什么能捕捉组合效应？ 如果特征 A 和 B 单独无增量，但 A+B 在模型中产生交互，全量矩阵中 score_full 包含了 A+B 的组合增益。尝试剔除 A 时分数下降（因为失去搭档），A 被保留。同理 B 也被保留。

淘汰规则

情况处理
本轮未被剔除接受，移入已接受特征集
被剔除，consecutive_rejects < 2 且 age ≤ 3留在池中等下轮
连续被剔除 ≥ 2 次永久淘汰
age > 3 轮永久淘汰
池中超过 20 个按 MI 分数淘汰最弱的

src/search/pending_pool.py + src/evaluation/validator.py

评分 综合评分机制

src/evaluation/validator.py — compute_composite_score()

通过 L3 验证的特征会获得一个综合分数，用于岛屿记忆库的排序和 Boltzmann 采样权重：

Score = 0.35 × norm(1/SHAP_rank) + 0.25 × norm(MI) + 0.25 × norm(1-redundancy) + 0.15 × norm(ΔPR-AUC)

其中 norm() 是基于历史值的 min-max 归一化，确保各指标在 [0, 1] 范围内可比较。

指标权重含义
1/SHAP_rank0.35在模型中的重要性（权重最高，因为直接反映对预测的贡献）
MI0.25与标签的信息量相关性
1-redundancy0.25与已有特征的非冗余程度（越低越好）
ΔPR-AUC0.15模型增量贡献

循环 搜索循环与收敛

src/search/engine.py

搜索引擎的主循环每一轮执行：

  1. 遍历 4 个岛屿，根据 SHAP 动态分配每个岛屿的候选预算（薄弱维度分配更多）
  2. 对每个候选执行 L1 → L2 → L3 验证
  3. L2 通过但 L3 未通过的特征 → 进入缓刑池
  4. 通过验证的特征加入岛屿记忆库 + 迁移到其他岛屿
  5. 更新 existing_features 矩阵（后续候选的基线随之增长）
  6. 失败的候选记入失败记忆（最多保留 50 条）
  7. 执行缓刑池反向淘汰评估
  8. 检查收敛条件

收敛条件

系统在以下任一条件满足时停止搜索：

  • 连续 2 轮没有任何新特征通过三级验证（包括缓刑池接受的特征也计入新特征）→ 搜索空间已被充分探索
  • 达到最大轮数 T=10（可配置）

失败记忆机制

src/search/memory.py

每个失败的特征都会被记录（名称、代码、失败原因），最近 5 条失败会注入下一轮的 User Prompt，告诉 LLM「不要再尝试类似的方向」。这避免 LLM 在同一个死胡同里反复浪费 token。

解释 特征可解释性报告

src/search/engine.py — _generate_explainability()

每个通过 L3 验证的特征会额外调用一次 LLM，生成结构化的可解释性报告：

字段含义示例
value_meaning不同取值区间的业务含义"值=1 表示正常，值>3 表示批量注册嫌疑"
risk_threshold高风险阈值及判断依据"阈值=3，基于异常交易 75 分位"

报告输入包含该特征在正常 vs 异常交易上的分布统计（中位数、均值、分位数），帮助 LLM 给出具体的数值阈值。

创新 核心创新点

1. 领域知识增强

首次将结构化专家知识（访谈 + 200+ 识别点 + 监管规则）系统性注入 LLM 特征生成。现有方法（LLM-FE、CAAFE、MedFeat）都缺乏深度领域知识注入。

2. 多表关联

首次将 LLM 特征工程扩展到多表关系型数据（开户 + 交易 + 销户三表）。所有 6 篇参考论文均仅支持单表输入。

3. 维度岛屿 + SHAP 搜索

改进 LLM-FE 的随机岛屿为按风险维度划分的 4 个有方向岛屿，结合 MedFeat 的 SHAP 引导，实现有分工 + 有方向的高效搜索。

4. 四级验证框架

代码验证 → 统计验证 → 模型验证 → 稳定性验证。超越现有论文（无一使用统计检验）的验证深度。

5. 可解释特征

每个特征附带领域依据说明和知识来源引用，满足金融监管的可解释性要求。

6. 缓刑池反向淘汰

解决特征组合效应问题。L2 通过但 L3 单独不够的特征进入缓刑池，每轮末通过反向淘汰发现组合有效的特征。现有方法（CAAFE、LLM-FE）均逐个评估，无法捕捉交互。
